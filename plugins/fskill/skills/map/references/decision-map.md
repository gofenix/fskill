# 决策图的存储与状态

在创建、恢复或修订共享决策图时读取。先检查项目已有 tracker 操作说明、导航和数据约定；不要求安装特定平台或固定 CLI。

## 单一事实来源

- **图**是一个索引对象，可以是 tracker 的父 issue，也可以是本地 Markdown 索引。
- **决策票**各自有唯一标识与详情位置。图只保留一行结论摘要及链接，不复制完整论证。
- **阻塞边**优先使用 tracker 原生关系，使协作者可直接查询；平台没有原生能力时，以明确的 `blocked-by` 标识列表表示。创建票后再用真实标识连边。
- **认领**沿用平台已有 assignee、owner 或 claim 机制；本地文件使用 owner 与认领时间。不要把既有负责人擅自改成自己，也不要把分配给其他协作者当成自己的认领。
- **本地草稿**放在用户或项目认可的位置；没有约定时先给建议路径，避免临时规划自动变成仓库长期文档。

保留项目已有标签和状态约定。需要专属类型时可用 `map:research` 等清晰标签，但不把决策票伪装成实施队列，也不强制替换原标签体系。

## 图索引

```markdown
# 目标名称

## 终点
全程最终要澄清或决定什么；满足什么条件即可交给后续工作。

## 约束
范围、真实授权、用户本轮预算与项目已有约定。

## 已定决策
- 决策票名称: 一行答案摘要与实际票据链接。

## 尚未明确
范围内但还不能准确表述的问题区域。

## 范围外
已排除事项与原因；需要时链接原票。
```

开放票从父子关系或索引数据查询，不在正文复制一份会失效的完整队列。本地 Markdown 缺少可查询的父子关系时，可保留只含票名、标识、路径和状态的票索引；正文问题与答案仍只存在各票。

## 决策票

沿用现有模板；没有模板时，用下面的最小字段表达协作所需事实：

| 字段 | 内容 |
|---|---|
| 名称与问题 | 一个明确要解决的问题，而不是开发动作 |
| 所属图 | 父对象或实际索引链接 |
| 类型 | 研究、原型、讨论、决策前置任务 |
| 参与方式 | agent 可独立推进，或必须有真人回答 |
| 解决条件 | 哪项事实、选择或证据出现后才算解决 |
| 状态与认领 | 开放、已解决、被替代或范围外，以及实际 owner |
| 阻塞 | 必须先解决的票标识；没有则为空 |
| 结论 | 答案、证据链接、真实取舍、后续影响 |

类型决定取证方式，不提供额外授权：

- **研究**：回答决策所依赖的事实。先定问题、证据标准和停止条件；资料冲突时保留冲突，不把搜到一篇文章视为定论。
- **原型**：用低成本、可丢弃的具体结果供真人评价。记录验证了什么、没有验证什么；原型选择仍属于真人。
- **讨论**：澄清约束、语义或偏好。问题简短，说明为什么会改变路线；已有代码能回答的先读代码。
- **前置任务**：取得访问权限、样本或环境等必要条件。写明解锁的决策；产品功能交付不属于此类型。涉及外部账户、费用、数据或部署时沿用任务实际授权。

## 前沿与并发

**可认领前沿 = 开放 + 所有阻塞票已解决 + 尚未认领。** 范围外、被替代、等待真人回答且无人能代答的票不作为 agent 可独立完成的下一项。

1. 查询最新状态，不依赖上轮缓存。
2. 认领目标票后复读，确认 owner 和阻塞没有变化；平台支持条件更新时优先使用。
3. 发现他人先认领或依赖变化时退回前沿重选，不覆盖对方状态。
4. 本轮未解决的票留下具体进展、剩余问题和认领状态；交接或释放认领遵循现有机制与授权，不伪造完成。

并行研究只用于互不依赖的问题；人工讨论的并发量由真人预算决定，避免多个会话重复追问。平台无法保证认领互斥时，明确这种限制。

## 解决、替代与范围变更

结论先满足解决条件，再记录到该票唯一详情落点。是否用正文、附件或 resolution comment 沿用现有机制；发布评论和关闭票仍需要本任务明确授权。操作后复读实际结果；没有执行就交付完整可审阅内容。

- 更新索引时只追加或替换一行摘要链接。
- 结论暴露可明确表述的新问题时建新票、连依赖，并从“尚未明确”移除对应区域；只暴露一个模糊区域则保留为迷雾。
- 发现已建票超出终点时，将其视为范围外，保留原因与链接；在获准修改状态前，不让它被误选为可推进前沿。
- 旧决策被证据推翻时保留历史，标明新结论与替代关系，检查所有消费者和依赖票；不静默改写过去的依据。
- 用户改变全程终点时重新评估范围和完成条件。原范围外工作不会自动回到前沿。

图完成的证据是必需决策全部解决、范围内迷雾为空且剩余阻塞已解释；关闭父 issue、写一份规格或执行实现都不能代替这些条件。
