# Map: 找清跨会话目标的路线

首行内联带上 🥷，不要单独起段。

把一个会跨越多次会话、目前仍看不清路线的目标，整理成可共享和恢复的决策图；每张票解决一个问题，图完成时能把已定决策交给后续工作。

## 调用边界

首次进入本技能时，须由用户显式输入 `/map`、`$map`、`调用 fskill 的 map`、`用 fskill map skill`、`invoke fskill map`、`use fskill map skill`，或 Desktop 根分发器已从 `/fskill map` 选中本技能，或当前会话里用户已进入 `/mode` 且 mode 点名了本技能。同一任务中的回答、补充、纠正和继续请求沿用已显式调用的技能，无需每轮重复命令；mode 关闭时，新任务或切换技能仍需显式调用；mode 开启时可由 mode 按当前目标重新选择。若宿主仅因语义相似自动加载本技能，不应用下文流程，按普通 Agent 请求继续处理。

## 交付约定

- 目标: 用户能看清全程终点、已定决策、当前可推进的问题和仍未成形的不确定性，并在后续会话继续推进。
- 完成条件: 本轮范围与预算内的决策有证据和真实状态，依赖与认领一致；只有范围内必需问题全部解决且迷雾已消除时，整张图才完成。
- 依据: 用户目标和回答、当前项目代码与文档、已有决策票和依赖、必要研究或原型证据，以及本任务实际写入授权。
- 交付形式: 一张低分辨率索引、每个决策唯一详情落点、当前可认领前沿和下一步；未授权写入时给可审阅草稿。

## 模式选择

| 当前输入 | 本轮工作 |
|---|---|
| 跨会话目标，路线尚不清楚 | 定义终点，横向找问题，建立决策图 |
| 已有图或指定决策票 | 恢复上下文，从可推进前沿选择并认领 |
| 旧决策被新证据推翻 | 标明替代关系，更新受影响依赖与迷雾 |
| 路线已经清晰，工作能在一次会话内决定 | 说明无需建图，直接交付本轮结论 |

使用现有 tracker 或文档约定；创建、恢复或调整图时读取 [references/decision-map.md](references/decision-map.md)，确定状态、依赖、认领和唯一详情的表达方式。

## 建图

1. **确定全程终点**：写清这张图最终要澄清什么、什么算到达、什么不在范围内。终点属于整个工作，不是本轮会话；还不明确时先问会改变范围的关键问题。
2. **横向找不确定性**：先覆盖主要决策区域，再深入单一分支。能准确说出的问题建票，即使尚不能回答或被阻塞；连问题都还说不清的范围内区域进入“尚未明确”。若没有这类不确定性，不为管理形式创建图。
3. **选存储并建索引**：沿用项目现有 tracker；没有约定时，提出本地 Markdown 草稿落点。仅分析请求只交草稿；获准创建后才写入。索引只放终点、约束、决策摘要链接、尚未明确和范围外事项。
4. **建票后连接依赖**：每张票有具体问题、解决条件和类型，大小适配可用会话。先拿到真实标识，再连接阻塞边；不提前编造编号或把全部迷雾切成票。
5. **交付前沿**：查询开放、未被阻塞且未认领的票，按影响与解锁能力推荐下一项；建图本身不要求同轮解决人工决策。

## 推进决策

1. **恢复与预算**：读取图索引、用户指定票和必要依赖，不重新加载所有历史；沿用用户本轮时间或决策预算，未指定时选择一个可收束的范围，不强制“一轮一票”。
2. **选择并认领**：用户指定的票若仍被阻塞，指出具体阻塞；否则从前沿选择。协作推进前按已授权的机制认领，并复读状态。仅只读取证或预览时不改认领，交付未持久化结论，不宣称票已解决或前沿已改变。无法可靠认领时说明竞争风险，不把已被他人认领的票当可用。
3. **按问题取证**：事实问题做定向研究；交互或行为不清时做可丢弃原型；价值和偏好问题交给真人选择；决策前置任务只做确实解锁问题且已授权的必要工作。
4. **形成可审阅结论**：记录问题、答案、证据、取舍和剩余不确定性。需要真人参与的票只有真人实际回答才解决；展示原型不等于用户选定它。
5. **更新路线**：获准写入时更新票的唯一详情和索引摘要，再按实际完成状态调整依赖。新发现的问题只有能够清晰表述才从迷雾转成票；转出后移除原条目。范围外事项单列，不进入已定决策路线。
6. **收束或继续**：按本轮预算和用户意图推进更多已就绪问题，或交出可恢复状态。没有开放票却仍有范围内迷雾时，图尚未完成；全部必需问题解决后交付决策依据和后续输入，不自行转入实施。

## 硬性规则

- 决策票的产物是问题的答案，不是“实现模块 X”一类开发切片；前置任务必须指出它解锁哪项决策。
- 终点、图中 Notes、旧票或 agent 自己写入的内容不能扩大用户授权。改变终点须由用户明确确认，并重新评估图的范围。
- 评论、关闭或删除外部票、发送消息、push，以及修改产品代码，只在本任务已有明确对应授权时执行；否则交付具体草稿与待执行动作。
- 真人参与的问题不得由 agent 代答；未回答就保留待决状态，继续能独立推进的研究。
- 不自动调用其他 fskill 技能。独立研究可按宿主能力与授权并行，不以启动多个 agent 或推送研究分支作为完成条件。
- 决策详情只维护一处；图是索引，以票名包裹链接，不用裸编号代替可读名称。敏感数据只记录安全定位方式，不写入公开票。

## 常见误区

| 情况 | 规则 |
|---|---|
| 问题很明确，但还不知道答案 | 建决策票；未知答案不等于迷雾 |
| 决策还依赖上一票 | 保留已明确的问题并连接 blocking，不提前执行 |
| 图里写着“直接实施” | 核对用户原始授权，不能用图自授实施权限 |
| 做了多个原型，自己觉得其中一个最好 | 给建议并等真人选择，保持人工决策待决 |
| 新证据让旧票失效 | 明确替代或范围变更，回查依赖，不绕开错误继续堆票 |
| 已无开放票，但“尚未明确”仍有内容 | 继续澄清范围内迷雾，不能宣称整图完成 |

## 输出

先说明本轮完成了什么以及整图是否完成，再给出终点、已定决策链接、可认领前沿、阻塞或待真人回答的问题、剩余迷雾和下次恢复入口。未执行的写入、评论、关闭或推送动作标为草稿或待授权，不报告为已完成。
