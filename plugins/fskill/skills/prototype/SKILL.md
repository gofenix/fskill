# Prototype: 用可运行实验回答一个问题

首行内联带上 🥷，不要单独起段。

把难以只靠讨论判断的不确定性变成能操作、能观察、能推翻假设的实验；交付原型和实验判定，不默认升级为正式实现。

## 调用边界

首次进入本技能时，须由用户显式输入 `/prototype`、`$prototype`、`调用 fskill 的 prototype`、`用 fskill prototype skill`、`invoke fskill prototype`、`use fskill prototype skill`，或 Desktop 根分发器已从 `/fskill prototype` 选中本技能，或当前会话里用户已进入 `/mode` 且 mode 点名了本技能。同一任务中的回答、补充、纠正和继续请求沿用已显式调用的技能，无需每轮重复命令；mode 关闭时，新任务或切换技能仍需显式调用；mode 开启时可由 mode 按当前目标重新选择。若宿主仅因语义相似自动加载本技能，不应用下文流程，按普通 Agent 请求继续处理。

## 交付约定

- 目标: 用最小可运行实验回答一个明确的领域逻辑或 UI 结构问题。
- 完成条件: 问题、判定标准和隔离边界明确，原型可运行，实际观察与假设分开，结论和未测部分可追溯。
- 依据: 用户要降低的不确定性、当前领域规则、现有页面与运行入口、实验输入、操作记录及实际输出。
- 交付形式: 原型文件或 URL、运行方式、问题与判定、未测范围及进入正式实现的条件。

## 模式选择

| 待回答问题 | 读取资源 | 实验产物 |
|---|---|---|
| 状态、事件、业务规则或数据形状能否表达实际场景 | [references/logic.md](references/logic.md) | 单文件 HTML，领域操作与可重置导引场景 |
| 信息层级、布局或主要操作结构哪种更合适 | [references/ui.md](references/ui.md) | 同一页面语境下可切换的结构方案 |

先用一句话写出问题和什么观察会改变判断。仅需调字体、颜色或间距时属于视觉设计；目标行为已经确定、用户要交付生产功能时属于正式实施。说明对应边界，按用户任务继续，不自动调用其他技能。

## 实验流程

1. **确定判据**：读取相关代码和领域约束，写明问题、假设、对照条件及可观察的支持或反证。高影响歧义先澄清；能从项目查到的事实直接查。
2. **限定实验**：选择一个模式，确定文件或路由、输入数据、运行入口、外部副作用替身和清理方式。保留现有用户工作；仅要求分析时不创建原型。
3. **构建并运行**：实现足以区分假设的行为，按对应参考暴露相关状态。使用项目已有运行入口或独立 HTML，不为了原型新造构建体系。
4. **记录判定**：运行能改变结论的场景，记录实际输入、操作和输出。用户尚未体验的偏好保留待确认；无法运行时交付入口和验证缺口，不把静态代码阅读写成实验已通过。
5. **交接去向**：说明哪些结论已获得支持、哪些逻辑可能复用，以及正式实现还需哪些集成、验证和错误处理。保留或删除实验、提升生产代码和写长期决策分别遵循本任务授权。

实验完成的依据是问题得到支持、反证或明确的证据不足；页面能打开本身不算回答了问题。

## 硬性规则

- 原型从文件名、路由或页面标记上可识别，默认内存状态；问题确实涉及持久化时使用明确隔离的临时数据。
- 外部写操作使用 stub，除非实验问题和现有授权明确要求真实写入；真实调用的对象、影响及验证方式要先确定。
- 一次性原型不默认补单测；问题依赖数值、状态不变量或重复实验才能判断时，运行对应的最小验证。
- mock、模拟状态和视觉比较只能支持其覆盖的假设，不能证明生产集成、权限、并发或真实数据安全。
- 不自动创建分支、commit、push 或 issue，也不因原型获认可就把实验代码直接并入生产。

## 常见误区

| 情况 | 规则 |
|---|---|
| 开始编码却说不清要回答什么 | 先写问题、可观察判据和会推翻假设的场景 |
| 多个方案只换颜色和文案 | UI 实验比较结构差异，方案数量由待判定问题决定 |
| 模拟页面成功就宣布端到端通过 | 标明替身和未测的真实链路 |
| 用户选中方案后直接发布原型 | 先交付结论和提升条件，再按正式实施授权承接 |

## 输出

- **问题**：本次要降低的不确定性与判据。
- **原型**：路径或 URL、运行方式和操作入口。
- **观察**：实际执行的输入、场景及结果。
- **判定**：假设被支持、被推翻或证据不足。
- **未测**：替身、真实集成及尚未获得的用户反馈。
- **提升路径**：值得保留的逻辑或结构、正式实施所需验证，以及原型去向。
