# 设计参考

这是 `/ui` 的完整参考。需要做较大界面设计或截图迭代时读取。

## 从用户场景出发

- 先理解用户和使用场景。工具型产品要安静、高密度、可重复操作；游戏和创意界面可以更表现性。
- 现有设计系统优先。读组件、设计变量、图标库和页面惯例，不要凭空发明风格。
- 第一屏应是可用体验，不是营销介绍，除非用户明确要落地页。
- 常见工作流必须顺手：进入、编辑、保存、回退、失败、空状态都要完整。

## 控件选择

- 工具按钮用图标，优先 lucide 或项目已有图标库。
- 模式用分段控件，二元状态用开关或复选框。
- 数字用滑块、步进器或输入框。
- 多选项用菜单或标签页。
- 不熟悉的图标要有提示文字。

## 布局

- 固定格式元素要有稳定尺寸：画板、网格、工具栏、图标按钮、计数器、图块。
- 不做卡片套卡片。
- 页面区块采用全宽分区或无框布局；卡片只用于重复项、模态框或真正需要边框的工具。
- 文本不能覆盖前后内容，长词不能挤出容器。默认自然换行；孤行先检查容器宽度和强制断行，不为凑行数删除有效信息、缩小字号或收窄容器。仅在保留含义和限定条件时精简重复，标题平衡需检查实际容器及语言。
- 不用视口宽度缩放字号。

## 视觉系统

- 字体大小和容器匹配：首屏主视觉才用大字号，工具面板用紧凑标题。
- 字间距默认 0，不用负值。
- 限制单一色相大面积使用，尤其避免整页紫/蓝紫、米色、深蓝、棕橙。
- 悬停、激活、聚焦、禁用、加载、空状态、错误状态都要设计。
- 图像要揭示真实产品、地点、对象、状态或玩法，不用模糊、带素材库感的氛围图。

## 首屏主视觉规则

只有真正需要落地页时才做首屏主视觉。首屏主视觉要用相关真实图片、生成位图或沉浸式交互背景，文字叠在背景上，不放卡片里。第一屏必须露出下一区块的一点内容。

品牌、产品、地点、人物页面，第一屏必须明确显示主体，不要只放在导航小字里。

## 3D 规则

3D 用 Three.js。主 3D 场景全幅或无框，不放在装饰卡片里。完成前用浏览器截图和画布像素检查：非空、构图正确、会动或可交互、资源加载成功、桌面和移动都不重叠。

## 改版顺序

已有产品先小步提升：

1. 字体替换或字体尺度。
2. 颜色清理。
3. 悬停、激活、聚焦状态。
4. 布局和留白。
5. 替换缺乏特色的通用组件。
6. 加载、空状态、错误状态。
7. 细节排印。

这个顺序能减少影响范围。
