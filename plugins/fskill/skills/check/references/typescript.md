# TypeScript 边界与状态检查

仅在目标 diff 使用 TypeScript 时读取。先读项目 tsconfig、lint、schema 与 API 兼容约定，运行其已有检查；模式是定位风险的方法，不是统一改写项目的理由。

## 输入与已验证模型

外部输入先保持 `unknown`，通过真实解析或 guard 得到领域模型。检查 guard 是否验证后续操作依赖的字段、分支和约束，不能只检查对象存在便断言整个类型。项目已有 schema 时优先由它推导类型，避免类型定义和运行时验证各维护一份。未知字段是否保留、拒绝或忽略服从协议和兼容承诺。

`as`、非空断言和 suppression 需要可追溯的前提与覆盖；它们可能适用于受限库边界，不能作为外部数据已验证的证明。不把断言数量作为问题数量。

## 互斥状态与构造约束

当不同状态允许的字段或操作不同，检查判别联合能否让非法组合无法表达，并在状态扩展时暴露遗漏分支；沿用项目穷尽检查约定。分别 optional 的字段不自动形成互斥关系。

表示替换后实际尝试构造反例。`{start: Date, durationMs: number}` 仍接受负时长和无效日期；要承诺有效范围，必须有受控构造入口的运行时验证或项目已有精化类型，而非换个字段名称。非空集合的 head/rest 表示也要确认调用者不能绕过构造与后续变更约束。

只有混淆语义 ID 已造成真实操作风险时才考虑区分类型；品牌形状、命名与构造沿项目约定，不引入仅为精确而存在的类型层。参数是否用对象由调用方可读性、可选项和演进需要决定，不强制所有函数改签名。

## 验证

把静态拒绝与运行时拒绝分开验证：非法状态应被实际类型检查拒绝，坏输入应在真实边界被拒绝，合法与兼容输入继续通过。由需求提供预期；仅有类型编译成功不能证明解析、数据持久化和消费者行为正确。
