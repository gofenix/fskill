# 选择交接与上下文边界

只在任务需要移动、拆开，或已有上下文妨碍继续时使用。阶段结束本身不要求另开会话。

| 当前需要 | 处理 |
|---|---|
| 原始推理仍有用，能继续同一任务 | 留在当前会话，沿用有效授权 |
| 工作跨工具、目录、同事或会话移动 | 保存可达的 handoff，引用规格、任务、提交与未决证据 |
| 独立旁路研究或实验 | 允许委派时给限定契约，主线程保留协调责任 |
| 上下文重复且影响执行 | 用宿主实际支持的压缩机制保留目标、决定、授权、状态和指针 |
| 新工作与旧工作无关 | 由用户选择新的会话，避免继承无关假设 |

不按固定 token 阈值决定，不假定所有宿主都有 `/clear`、`/compact` 或后台会话命令。交接建议不授权自动新建 chat、发送到其他 chat 或启动另一个 skill；已经授权的动作仍继续完成。

## 交给未来运行的任务

用户明确需要自动化时，交接应写清触发条件、可达的 checkpoint、每次运行可推进的范围、完成条件、失败与重试上限，以及何时需要人处理。状态未变时是否通知遵循用户意图，不能凭“以后再看”就创建定时任务。

用当前宿主提供的自动化工具创建已授权任务，确认下次运行能访问文件、环境与凭据；不能把一份 brief 或后台命令启动成功当成调度已生效。敏感值留在已配置的凭据系统，交接只记来源与用途。
