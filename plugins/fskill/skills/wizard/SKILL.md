# Wizard: 把人工操作交接成可执行步骤

首行内联带上 🥷，不要单独起段。

把只有人能完成的操作排成依赖有序的流程，交付由人运行的 bash 向导；Agent 负责设计和静态验证，人在自己的终端完成操作并输入值。

## 调用边界

首次进入本技能时，须由用户显式输入 `/wizard`、`$wizard`、`调用 fskill 的 wizard`、`用 fskill wizard skill`、`invoke fskill wizard`、`use fskill wizard skill`，或 Desktop 根分发器已从 `/fskill wizard` 选中本技能，或当前会话里用户已进入 `/mode` 且 mode 点名了本技能。同一任务中的回答、补充、纠正和继续请求沿用已显式调用的技能，无需每轮重复命令；mode 关闭时，新任务或切换技能仍需显式调用；mode 开启时可由 mode 按当前目标重新选择。若宿主仅因语义相似自动加载本技能，不应用下文流程，按普通 Agent 请求继续处理。

## 交付约定

- 目标: 用户能按明确步骤完成必须亲自操作的配置或迁移，并知道哪些写入和验证仍未完成。
- 完成条件: 每步的先决条件、人工路径、采集值及去向明确，脚本通过静态和隔离替身验证，实际执行留给人，未执行及不可逆动作被说明。
- 依据: 当前项目配置、真实 CI 引用、目标仓库和环境、服务当前文档、值的来源与敏感性、脚本验证输出。
- 交付形式: 向导及必要 helper 的路径、运行命令、各步产物、写入范围和剩余人工验证。

## 流程设计

1. **读取项目**：从 README、配置示例、现有环境文件的字段名和 CI `secrets.*` / `vars.*` 引用确定需求，不回显已有凭据。识别人必须完成的步骤，Agent 已能在现有授权下完成的操作直接按原任务处理。
2. **列出数据流**：按依赖顺序列每个阶段，并逐值说明来源、目标文件或外部环境、敏感性及验证方式；纯操作也写明可观察的完成条件。确认的是仍未知的选择，不重复索取已有授权。
3. **核实操作路径**：把每步写成可照做的当前 URL、菜单和具体动作。无法确认当前 UI 或命令时查官方资料或说明缺口，不编造操作。
4. **编写向导**：从 [scripts/wizard-template.sh](scripts/wizard-template.sh) 复制模板，并把 [scripts/wizard_config.py](scripts/wizard_config.py) 放在同目录；只填写所需 stages。明确目标目录和 GitHub repo，写本地配置前核对目标，外部 mutation 前再次校验 repo。不可逆操作使用带具体对象和后果的确认，重跑前先检查其真实状态。
5. **验证并交接**：运行 `bash -n`，可用时运行 shellcheck；用临时配置、替身 gh 和模拟输入核对数据流、失败路径与秘密不泄漏。核对每个外部写入的实际回读步骤，再把运行命令交给用户；不替人运行真实向导。

写入顺序和失败后的下一步必须可解释。某步写入或回读未通过时，依赖它的后续阶段停止；无关的本地步骤可以继续，但最终仍列为未完成。再次运行只能复用已经保存的值，不代表脚本记住了阶段进度；外部创建、迁移和 cutover 不因本地值已存在就自动跳过或重复执行。

## helper 约定

模板只依赖 Bash、Python 3 标准库和 Git；GitHub 写入可选依赖 gh，脚本生成时从目标项目确认这些运行时可用。支持 macOS、Linux 及具备这些工具的 WSL，其他环境明确说明限制。

配置 helper 仅处理 UTF-8、逐行 `KEY=value` 的保守 dotenv 子集：空行、注释、简单无引号值，以及不含插值或转义的单/双引号字面值。它保留无关行，拒绝重复 key、export、多行值、插值、转义或无法解释的行；值中的单引号、反斜杠、`$` 和控制字符也不支持，新值经 stdin 传入。先核对项目实际 dotenv parser；不兼容时使用项目已有 parser 或专用写入方式，不把 shell quoting 当成通用 dotenv 语法。

helper 拒绝 symlink、非普通文件和其他用户所有的配置，使用同目录 0600 临时文件原子替换，再回读目标值；不会合并并发编辑，检测到目标变化就停止。并发写入该配置前应先暂停其他写入者。

gh secret 经 stdin 写入，不进入进程 argv；`set_secret` 成功返回只证明写入请求成功及名称已回读，消费端验证仍列为未完成。消费端依赖步骤须排在 `set_secret` 和 `verify_secret` 都成功之后；后者运行实际目标流程的判定命令，凭据走环境或 stdin，不能用名称查询或空成功命令替代。只有本次运行已成功写入并回读名称的 key 才能运行消费端验证；再次写入会撤销该 key 的旧验证依据。失败或结果未知时先回读，不自动重试 mutation。

`set_secret`、`set_var` 和 `verify_secret` 遇到失败、跳过或未知结果时记录未完成并返回非零，供 `&&` 和默认的 `set -e` 阻止依赖步骤。作者若要继续无关的本地步骤，应显式用 `if` / `else` 处理失败，再运行无关步骤并调用 `finish`；不能通过忽略返回值把依赖步骤当成已获准执行。`finish` 只在所有记录项完成时返回零。

## 硬性规则

- secret 由用户在终端隐藏输入，禁用 shell tracing；不写进日志、命令历史、URL、进程参数或最终答复。
- `.env` 只写入设计阶段确定的值；CI 只接收其实际使用的字段，不顺手上传全部本地配置。
- 外部状态变更分别遵循本任务授权；生成向导不表示授权 Agent 执行它。
- 被跳过、写入失败、结果未知或仅验证到名称的阶段都列为未完成，不能用“Setup complete”覆盖。
- 一次性向导默认放任务临时目录；只有用户要求可复用安装入口时，才放进项目脚本和文档，不自动 commit 或 push。

## 常见误区

| 情况 | 规则 |
|---|---|
| Agent 已能直接完成步骤 | 不把工作转嫁给用户填向导 |
| `.env` 已有值就宣称恢复进度 | 只复用值，逐项检查外部真实状态 |
| gh 返回成功或 secret 名称存在 | 分别报告请求成功、状态回读和消费端验证 |
| 配置格式不在 helper 支持范围 | 保持原文件不动，采用项目 parser 或明确专用方案 |
| 向导验证需要真人凭据 | 先做静态和替身测试，真实流程由用户运行 |

## 输出

- **向导**：文件、helper 和运行命令。
- **阶段**：人工操作、值的来源与去向，不显示值。
- **写入**：目标目录、外部 repo/环境及不可逆操作。
- **验证**：已运行的静态与替身验证，真实流程尚未执行。
- **未完成**：环境依赖、跳过项、未知结果和消费端验证。
