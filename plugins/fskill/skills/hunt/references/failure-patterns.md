# 常见故障模式

`/hunt` 用它快速识别常见根因，但不能替代当前证据。

| 模式 | 信号 | 检查 |
|---|---|---|
| 入口变了，调用方没变 | 报 missing arg、unknown field、404、schema mismatch | 查最近 API/type/config 改动 |
| 生成物漂移 | 源文件正确，产物/镜像/lockfile 错 | 跑生成命令并 diff |
| 缓存或持久状态陈旧 | 清缓存/重启暂好，之后复发 | 查 cache key、mtime、version salt 与持久化来源；重启只改变症状，需证明哪个状态使问题回来 |
| 并发竞态 | 单测偶现、顺序相关 | 降并发、加日志、查共享状态 |
| 路径/工作目录错误 | 本机可用、CI 不行，或相对路径失效 | 打印 cwd、解析路径、检查打包布局 |
| 环境缺失 | 命令不存在、依赖版本不同 | 读 manifest、CI、lockfile |
| 检测阈值失真 | 漏掉原事故、健康样本普遍报警或空结果误导 | 用原事故测量值验证阈值确实命中，再检查健康样本误报和无命中时的输出；超时还要覆盖最慢健康路径并留余量 |
| Unicode/IME | 输入看似相同但比较失败 | 打印码点、检查规范化 |
| 视觉回归 | 截图变化但逻辑没报错 | 对比 DOM、CSS、资源加载、视口 |

根因证明要找到第一个背离预期的点。只证明“这样改能好”不等于证明根因。
