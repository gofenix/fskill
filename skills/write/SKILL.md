# Write: 去掉 AI 味，保住原意

首行内联带上 🥷，不要单独起段。

## 交付约定

- 目标: 让文字自然顺口、符合目标读者与体裁习惯，同时完整保住原作者的意思、立场和情绪。
- 完成条件: 原意与事实边界都在，明显 AI 结构壳与标点错漏已清理；涉及文件时跑过随附检测脚本。
- 依据: 原文或作者素材、目标读者、当前真实产品/发布状态与目标语言参考。
- 交付形式: 粘贴文本默认直接给改稿（长文给变更点，对照模式给逐块结论）；仅要审稿时列问题与建议。

## 调用边界

仅在显式调用 `/write`、`$write`、fskill 限定入口或已开启的 `/f-mode` 选中时执行；同一任务里的追问继续沿用，**不自动切换技能**（`f-mode` 开启时除外）。不用于技术方案/spec 正确性审查（走 `/check`）或跨来源深度研究（走 `/learn`）。旧记忆仅提示声音偏好，不读原始对话且不授予发布权限，当前文本、产物与目标读者优先于旧记忆。

## 核心立场与编辑前判断

1. **原意与声音优先**：这个技能是气味目录，不是机械查找替换表。句子已经自然清楚就别动；保住作者立场与情绪，不把个人表达磨成通用腔，不为凑字数补造未发生的经历或意象。
2. **先读材料，按读者与语言选参考**：缺少文本或素材才索要；长文从零起草前先确认各节确有不同素材；中文正文读 [中文去 AI 味模式库](references/write-zh.md)，英文正文读 [英文写作参考](references/write-en.md)。
3. **长文编辑与对照模式**：长文（300+ 行）先当首次读者通读，遇到缺定义、空评价或未交代的人名立刻停在卡住的句子，再查跨节重复；**默认给改前 -> 改后变更点**，用户说“直接改”才重排或全改。对照两份稿子时逐块判断得失并点清丢了什么原意。
4. **发布说明与产品本地化**：**事实主张基于产物**（可运行版本、截图、release/PR）；**发布说明要工程师可读**，拒绝空话；不把参考版本的条数当硬配额。UI 本地化按控件长度/状态匹配，报错在已有真实恢复路径时写清下一步，不编造补救承诺；双语版本保证事实、语气与编号一致。
5. **硬规范与交稿**：新写或改写不用长破折号（U+2014 / U+2013）与括号插注，改用标点或重排；中文正文用全角引号，中英文间通常留空格（代码/路径/命令除外）。交付前悄悄剔除给人或 AI 看的核验备注与待办，不另列“已删备注”。

## 确定性脚本检查

待审文本来自文件或将写回文件时，定位当前技能根目录为 `SKILL_DIR`（Desktop 合包为包根下 `skills/write`），运行：

```bash
bash "$SKILL_DIR/scripts/check-punctuation.sh" --lang auto <file>
bash "$SKILL_DIR/scripts/check-ai-flavor.sh" --lang zh <file>
```

脚本仅作辅助判断，短消息润色无需建临时文件。涉及文件修改后先读 `git status --short --branch -uall`，用户手改过的删减坚决保留。
