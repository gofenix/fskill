# 改前改后对照模式

输入是同一段文字的改前/改后两份（未提交的 diff、两版草稿、别的模型或编辑的润色稿），问题是新版是否更好时，由 `write` 读取本文件。

完成条件是每个改动块都有结论（保留、还原或折中），每个还原或折中都指出新措辞丢了什么，重复这段文字的镜像面与新版本一致。要对着整篇文章读词级 diff（`git diff --word-diff`），不要孤立地看改动块：多数丢失只有对照上下文段落才看得出来。

润色稿常见的丢失，保留某个改动块前先检查：

- **原始反应换成工整的抽象。** 作者的感叹、口语或具象画面被换成一个中性名词短语（"摩擦"、"会心一笑"、"永远是最优先的事"）。新句读起来更顺，却不属于任何人。还原作者原话；折中可以保留新版在它周围的删减。
- **母题链条断了一环。** 标题、段落中段的一句和结尾段常回指同一个意象。把其中一处中性化，其余几处就悬空了。把链条当一个整体：要么全留，要么全改。
- **推理被砍成光秃秃的论断。** 为压长度砍掉取舍分句、"因为"或收尾立场，只剩一个读者自己也能写出的定义。被砍的部分正是这段的重点时，更短不等于更好。
- **具体数字或名字被模糊化。** "850 个全部免费可读"变成"点进任意一个 app 就能读"。把具体值还原。
- **新加的措辞与全文论点矛盾。** 文章把某件事写成刻意、费力的付出，前面却加了个随意的"顺带"。逐个核对新加的副词和框架词与全文主张是否一致。
- **改动引入了重复表述。** 同一句里同一个名词出现两次，或结尾的行动号召重复了上一段的请求。

更好的改动要接受：错字和语法修正、更真实的开篇动机、确实被误读的长句。作者问的是新版是否更好，不是要替旧版辩护，所以每个块都还原的审查同样失败；反过来，每个块都留也是。逐块按自身得失判断。

标题轻拿轻放。作者刚选定标题时，只有误读或误导才提。给出的备选必须在朗读时比原题更顺；只是更字面或更正确的备选会被否决，而且理应被否决。

结论之后同步各面：

- **镜像。** 只改了一种语言（英文改了数字、中文加了清单）就是漂移。把每个保留的改动带到另一版，或在两版上都还原。
- **标题回声。** 标题用词变化时，找出所有重复它的地方：封面或社交卡片图上的文字、图片 alt、镜像版标题、摘要字段、其他文章的交叉链接。图上的文字不再匹配标题时需要换图，不只是改 alt。

输出跟随请求。"是不是更好？"给按影响排序的逐块结论，只读。"改吧"给改动本身，外加一份作者可以否决的还原或重写清单。
