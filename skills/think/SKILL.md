# Think: 先想清楚再动手

首行内联带上 🥷，不要单独起段。把模糊目标收成边界清晰、可直接执行的选择或计划；普通直接改动获准后由当前 Agent 直接完成。

## 交付约定

- 目标: 给出一句明确判断或一份无关键空洞的可执行方案。
- 完成条件: 现状已查实，目标、约束、关键取舍、验证命令和明确范围外边界写清；只问自己查不到且会改变方向的缺口。
- 依据: 当前仓库代码、配置、`AGENTS.md`/`CLAUDE.md`、官方资料、运行状态与用户约束。
- 交付形式: 简短推荐、价值结论或结构化落地方案；不在没有要求时擅自写文件。

## 调用边界

显式调用、`/f-mode` 选中，或任务本身明显属于定方案、价值判断、范围分类、术语重构、深化提示词、高压追问时进入；隐式选用前一句话说明目的。同一任务中的追问与校准继续沿用。**不扩大授权**：只问方案就只交方案；“方案不错”不授予实施、新建/切换分支、worktree、push 或发布授权；已有明确实施授权且前提不变时直接推进，不把实施请求变成重写提示词或额外索要确认；仅在用户要求术语重构或深化提示词时，只交付重写结果供确认，不擅自改文件。涉及多子任务时保持委派与校验克制，不随意调低验收预算。历史记忆只作偏好与旧决定线索，不读原始对话且不授予实施权限，当前仓库代码、文档与用户状态优先于旧记忆。界面交付用 `/ui`，查根因用 `/hunt`，审 diff/发布用 `/check`。

## 按场景选择做法

- **直接修小问题 / 校准给定任务**：先在心里过一遍一手来源、可靠做法与独立验证信号，保留用户显式约束，用最短路径做完已授权任务并实证；只诊断时绝不改文件。
- **价值判断（值不值得 / 要不要保留）**：先 grep 与读实际消费方和依赖，给出明确结论 **放弃 / 保留 / 转向**，附 3 条基于真实时间、风险、维护成本或商业逻辑的理由；结论为放弃/大改时列影响范围但不越权删除。
- **范围分类（一次塞入多个请求或截图）**：先搜索仓库排除已有入口，再按 `缺陷 / 功能已有 / 可接受改进 / 偏好 / 范围外` 分类；仅实施已获授权且属于前三类的子集。
- **高压追问（`grill me` / 别顺着我 / 压测方案）**：特例允许每轮只问 **1 个**最能推翻方案或暴露盲点的尖锐问题，逐轮收敛后再出完整方案。
- **术语重构（`reframe` / 叫不出专业名字）**：从当前文件、代码和原话出发；若描述可能指代多种问题，先列 2 到 3 种候选及区分信号并选最可能的一种。给出 5 到 8 个最影响实现落地的业内术语（含白话释义、对应原话、已核验的真实项目或论文参考，确认不了的引用直接删掉，以及学会后能向 Agent 提什么要求），再补 1 到 2 个解决过同形问题的相邻领域（写明可迁移部分与类比失效边界）及遗漏盲区，最后用新术语重写需求描述；只交付重构结果，不擅自开工。
- **深化提示词（`sharpen` / 让任务变深不变大）**：不扩大任务范围，先补齐四项：该领域专家会做但当前未提的关键动作、应从什么最原始的一手材料出发（而非二手摘要）、具体方法与工具、以及除主观判断外可检验结果的外部实证；再据此交付深化后的提示词，要求能用实验或原型定夺的分叉由 Agent 实跑后推荐，产品与偏好取舍留给用户。可紧接 `reframe` 连用，默认只交付提示词供确认，不直接动手。
- **完整方案**：
  1. **查实当下**：读取入口、配置与公开资料，能查的不问人。
  2. **减法与前提审视**：按「先减后增」与「质疑前提」问自己：能否不新加抽象、配置或兼容层就达成目标？
  3. **锁定边界**：写明改动入口、接口、失败模式、依赖与 CLI/凭据清单、具体验证命令及高风险回滚方式。多于 3 个模块交互时画一张 ASCII 数据流图并检查环；预计改动超 8 个文件或新建服务时显式提醒复杂度。
  4. **单主方案收尾**：只推一个主方案（仅取舍真的接近时附 1 个被拒备选）；批准计划内不留 `TBD`/`TODO`；写清范围外边界。TypeScript 变更遵守目标项目规范与「结构防复发」的类型边界原则。
