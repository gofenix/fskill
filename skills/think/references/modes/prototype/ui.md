# UI 结构实验

当需要通过操作比较信息层级、布局或主要操作路径时读取。先写明方案之间要判定的差别；方案数量由问题决定，两个能区分假设的方案优于凑数的多个变体。

## 保持真实页面语境

优先在现有宿主页面内承载方案，保留 header、导航、权限和只读数据入口；仅替换待比较子树。一个新区域自然属于已有页面时，也放回该语境。确实没有合适宿主才沿用项目路由约定建立明确标记的临时页面。

各方案使用同一 host、route、数据和关键状态，避免布局差异与数据密度变化混在一起。先核对项目真实运行入口、端口及路由可用性；不能只交一组脱离应用背景的组件文件。

## 结构差异与切换

方案在布局、信息优先级或主要操作路径上形成可判断差异，同时沿用项目组件和样式体系。每个方案用一句话说明它优化什么、牺牲什么。共用数据和基本组件，但不强迫所有方案套进同一个布局骨架。

使用 URL 参数或项目既有机制切换，保留原有参数和路由状态，让同一个链接能重现当前方案。切换器与被评价内容区分，不遮挡操作。需要键盘切换时，仅在不会占用现有键盘行为的位置启用；不得截获 input、textarea、select、contenteditable 或已有键盘控件的方向键。

原型分支只在明确实验入口启用；生产默认路由保持原行为。所有外部 mutation 都指向 stub，表单、快捷键和自动提交路径也必须核对，不能只替换按钮回调。

## 运行与判断

用项目实际运行命令打开同一路由，在一致的数据、视口和关键状态下比较方案。记录是否完成目标操作、信息是否可找到、状态切换是否产生误解。截图只能证明当时渲染，不能替代操作证据或用户偏好。

交付运行命令、URL、方案标识与比较结论。用户选定结构后，说明生产实现需重做的错误处理、权限、真实 mutation 与验证；不自动保留所有变体、提升路由或发布原型。
