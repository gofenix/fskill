# Map: 找清跨会话目标的路线

首行内联带上 🥷，不要单独起段。

把一个跨好几次会话、现在还看不清全貌的大目标，拆成能共享和续接的决策图；每张票解决一个具体问题，整张图收尾时把敲定的结论交给后续开发。

## 调用边界

由父技能按当前模式读取后执行，不再是独立命令。同一任务里的补充和纠正沿用这个模式。不要因为话题相近就单独启动这一节。


## 交付约定

- 目标: 让用户一眼看清全程终点、已经定下的决定、现在就能推进的问题，以及还没摸清的未知区域，下个会话也能接着干。
- 完成条件: 这轮范围内每项决策都有证据和真实状态，依赖和认领情况对得上；只有范围内必需的问题都解决、未知区域都理清了，整张图才算完成。
- 依据: 用户目标和回答、项目现有代码与文档、已有决策票和依赖、必要研究或原型证据，以及这轮实际的写入授权。
- 交付形式: 一份总览索引、每项决策的唯一详情位置、当前可推进的问题和下一步；没有写入授权就交可审阅草稿。

## 模式选择

| 当前输入 | 本轮工作 |
|---|---|
| 跨会话目标，路线尚不清楚 | 定终点，横向摸排问题，搭起决策图 |
| 已有图或指定决策票 | 恢复上下文，从当前可推进的问题里选一项认领 |
| 旧决策被新证据推翻 | 标明替代关系，更新受影响的依赖和未知区域 |
| 路线已经清晰，一次会话就能决定 | 说明没必要建图，直接给这轮结论 |

沿用现有的 tracker 或文档约定；创建、恢复或调整图时读取 [references/decision-map.md](decision-map.md)，统一状态、依赖、认领和唯一详情的写法。

## 建图

1. **确定全程终点**：写清这张图最后要搞懂什么、什么算到达、什么不做。终点属于整件事，不是这一轮会话；如果还含糊，先问会改变范围的关键问题。
2. **横向摸排未知点**：先铺开主要决策板块，别一头扎进单条分支。能问清楚的问题就建票，哪怕现在还答不上或被挡着；连问题都还问不出来的范围内区域先放进“尚未明确”。如果压根没有这类不确定性，别为了流程硬造一张图。
3. **选地方存并建总览索引**：沿用项目现有的 tracker；没约定时提议一个本地 Markdown 草稿位置。只让分析就只交草稿，同意创建再写文件。索引里只放终点、硬约束、各决策的摘要链接、“尚未明确”和范围外事项。
4. **建完票再连依赖**：每张票对应一个明确问题、解决条件和类型，大小控制在单次或少数几次会话能推进完。先拿到真实票号再连阻塞关系，别提前编编号，也别把还没想清的未知区域全硬切成票。
5. **交出可推进的问题**：列出当前开放、没被阻塞也没人认领的票，按影响和能解锁多少下游推荐下一项；建图本身不要求当场把需要人拍板的决定全答完。

## 推进决策

1. **恢复现场与控制预算**：只读总览索引、用户点名的票和必要依赖，别把所有历史全倒进上下文；跟着用户给的时间或轮次预算走，没给预算就选一个能收束的小范围，不硬凑“一轮一票”。
2. **选票并认领**：用户点名的票如果还被卡着，指出到底卡在谁身上；否则从当前可推进的问题里选。协同推进前按已授权的方式认领，再核对一遍状态。只查证或看预览时不改认领状态，只交未落盘结论，别宣称票已解决或可推进列表已变化。没法可靠认领时提前提示撞车风险，别动别人已经在做的票。
3. **按问题性质去查证**：查事实就做定向调研；交互或行为拿不准就做个用完可丢的小原型；牵涉业务取舍和偏好的让真人拍板；前置小任务只做真能解锁问题且已授权的必要部分。
4. **写出可审阅结论**：记下问题、结论、证据、取舍和剩下拿不准的地方。必须真人定夺的票，只有人真的回答了才算解决；给用户看了一版原型，不等于用户已经拍板选它。
5. **更新路线图**：有写入权限时更新那张票的唯一详情和索引摘要，再按实际完成状态改依赖。新冒出来的问题，只有能表述清楚时才从未知区域拆成新票，拆出后把原条目删掉。范围外的事单列出来，别混进已定决策路线。
6. **收尾或接着推**：按这轮预算和用户意图接着解下一批已就绪问题，或者交出可续接状态。就算没开放票了，只要“尚未明确”里还有范围内没想清的事，图就没完；所有必需问题解决后，交出完整决策依据和后续输入，别擅自直接转进写代码。

## 硬性规则

- 决策票交付的是问题的答案，不是“实现模块 X”这种开发任务；前置解锁任务必须写清它到底为了解开哪个决策。
- 终点、图里的备注、旧票或 agent 自己写进文件的内容，都不能扩大用户授权。改终点必须用户明确点头，并重算全图范围。
- 评论、关闭或删外部票、发消息、push 以及改产品代码，只有当前任务明确授权了才能做，否则只交具体草稿和待办动作。
- 需要真人决定的问题，agent 不能替人瞎答；没收到答复就先标待决，接着推进能独立调研的事。
- 不自动调用其他 fskill 技能。独立调研可以按宿主能力和授权并行，但别拿“开了几个 agent”或“推了调研分支”当完成标准。
- 决策详情只在唯一一处维护；总览索引里用票名包上链接，别拿干巴巴的编号代替人能看懂的名字。敏感信息只记安全访问方式，别写进公开票据。

## 常见误区

| 情况 | 规则 |
|---|---|
| 问题很明确，只是现在还不知道答案 | 照样建决策票；未知答案不等于问题都没想清 |
| 决策还卡在上一张票上 | 保留已经想清的问题并连好阻塞关系，别提前硬做 |
| 图里写了“直接实施” | 核对用户原本的授权，别自己写几个字就给自己授实施权 |
| 做了几个原型，自己觉得其中一个挺好 | 给推荐理由然后等真人挑，保持人工决策待决 |
| 新证据把旧票结论推翻了 | 标清替代或范围变化，回头顺一遍受影响的依赖，别绕开错的接着堆新票 |
| 已经没有开放票，但“尚未明确”里还有东西 | 继续把未知区域聊清楚，不能对外宣称整张图完了 |

## 输出

先说清这轮搞定了什么、整张图到底完没完，再给出终点、已定决策链接、现在可认领的问题、卡住或等真人拍板的项、剩下的未知区域，以及下次从哪接手。没执行的写文件、评论、关闭或推送动作标成草稿或待授权，别写成已完成。
