# Domain: 厘清领域概念与边界

首行内联带上 🥷，不要单独起段。

把模糊、重载或互相矛盾的领域语言变成有明确适用范围的概念；用真实行为和反例检验，确认后再按授权落到项目已有术语与决策文档。

## 调用边界

由父技能按当前模式读取后执行，不再是独立命令。同一任务里的补充和纠正沿用这个模式。不要因为话题相近就单独启动这一节。


## 交付约定

- 目标: 用户和代码使用的领域概念具有可区分的含义，关键行为、事件与上下文边界不再靠含糊命名维持。
- 完成条件: 本轮范围内每个关键术语都已确认，或明确标为待决；用户说法、已有文档与代码的冲突有具体证据，获准写入的内容可被下次工作发现。
- 依据: 用户业务知识、当前代码与测试、公开项目文档、已有术语导航与 ADR，以及针对概念边界的具体情境和反例。
- 交付形式: 已确认概念、行为与边界、冲突或待决问题，以及实际文档变更或可审阅草稿；只在满足门槛时形成 ADR。

## 模式选择

| 需要澄清什么 | 工作重点 |
|---|---|
| 一个词指向不同对象，或不同词指向同一对象 | 词义、语境、推荐名称与歧义别名 |
| 行为、状态或事件的含义不清楚 | 谁发起、什么条件、状态如何变化、谁观察结果 |
| 多个模块或团队对同名概念各有定义 | bounded context、所有权与跨上下文翻译 |
| 本轮建模中确认的词汇需要保存 | 按现有落点增量记录，不重新开启整套建模 |

首次涉及文档落点、多上下文或决策记录时，读取 [references/domain-artifacts.md](domain-artifacts.md)。单纯读取现有术语或存档既定事实不需要重新建模；这一节在主动澄清中保存已确认结果，不自动切换其他 fskill 技能。

## 建模流程

1. **确定语境与问题**：锁定用户当前讨论的业务区域、参与者和具体困惑，读取既有术语与决策导航；只展开会影响本轮理解或选择的概念。
2. **找真实行为**：沿代码入口、状态转换、事件生产与消费、测试和持久化约束确认当前事实。把“当前代码这样做”“业务期望这样做”“正在考虑这样做”分开，不用其中一个自动覆盖另一个。
3. **提出可区分定义**：对重载词先给可能指向，再建议名称；说明每个概念是什么、何时存在、与相邻概念差在哪。命名服从项目已有语言，不机械套 DDD 类名或编造业务理解。
4. **用情境试边界**：选择会改变词义的具体反例，例如部分取消、重复事件、权限变化、跨生命周期或跨上下文引用。说明这是用于验证定义的假设情境，不把反例当已发生事实；已有代码能回答的先查，只有业务意图才能决定的再问真人。
5. **解决冲突**：并列用户说法、文档定义和代码位置，指出它们导致的不同结果；澄清是词义混淆、文档过期、实现缺口还是刻意差异。没有证据或真人决定时保留待决，不静默改名或改代码。
6. **收束与记录**：给出确认后的语言、关键行为和边界。用户已授权记录且落点明确时，随概念确认增量更新原文；仅讨论时交草稿。未确认概念不写成长期事实，ADR 单独按门槛筛选。

## 硬性规则

- 同一上下文同一概念用同一名称；不同 bounded context 可以有同名异义，分别定义并说明交互处如何翻译，不强制全局合并。
- 术语文档只保留项目特有的概念、短定义和需要避免的歧义词；实现细节、开发计划、测试规则和讨论流水放到相应现有落点。
- 沿用 `CONCEPTS.md`、`CONTEXT.md`、`GLOSSARY.md` 或模块级术语文件与导航，已有合适文件时不再造平行 glossary；没有内容需要保存时不建文件。
- 用户说法和代码不一致时给具体证据；代码证明当前实现，不能单独证明业务期望正确。代码重命名、行为修改与扩大审计范围遵循本任务授权。
- 只有已经确定且同时满足“难以逆转、脱离上下文会令人困惑、经过真实取舍”的决策才记录为 ADR，沿用项目模板与目录。
- 一次只追问能改变当前概念边界的关键问题，适配用户预算；真人未回答的业务选择不能由 agent 填补。

## 常见误区

| 情况 | 规则 |
|---|---|
| “account”在账务和身份系统各有意义 | 先辨认语境与所有权，再决定是否需要拆词 |
| 代码只有整单取消，业务要求部分取消 | 报告当前行为与期望差异，不能只改定义让两者看似一致 |
| 词汇文件很长 | 先去掉计划、实现与重复内容，只有真正存在多个语境才拆分 |
| 已选一个容易撤销的实现方案 | 不满足 ADR 门槛，记录在当前任务即可 |
| 用户同意术语，但只要求讨论 | 给可审阅定义，不把同意语义当文件写入授权 |
| 只有领域名词，无法说明边界情境 | 继续检验模型，不用“语言统一”代替业务理解 |

## 输出

用项目自己的语言给出已确认概念及适用语境、关键行为或事件、冲突的证据、剩余问题和文档状态。文档有变更时说明实际落点与导航；未写 ADR 时只在相关情况下说明哪个门槛未满足。没有未解决问题且完成了必要核对时，简洁收束。
