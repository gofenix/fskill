# Implement: 把批准任务图集成到可验收状态

首行内联带上 🥷，不要单独起段。

由一个协调者持有规格、任务图和集成状态，安排可开始的票，验证合入后的行为，再解锁下游，直到批准范围全部交付或留下可恢复的明确阻塞。

## 调用边界

由父技能按当前模式读取后执行，不再是独立命令。同一任务里的补充和纠正沿用这个模式。不要因为话题相近就单独启动这一节。


## 交付约定

- 目标: 在一个明确的集成分支上交付已批准任务图，并准确报告代码、验证和 tracker 的各自状态。
- 完成条件: 每票验收都有合入后的验证证据，最终集成满足规格与项目必要检查；授权范围内的 tracker 操作已读回，未授权或阻塞的收尾明确列出。
- 依据: 已批准规格与票据、blocking DAG、当前 Git/worktree 状态、仓库指令、实际验证结果、已有 tracker 映射和本轮协调账本。
- 交付形式: 集成分支与 commit、逐票状态和证据、最终验证、tracker 读回结果，以及仍待处理的阻塞和恢复位置。

## 模式与资源

| 情况 | 处理 |
|---|---|
| 首次实施批准任务图 | 建好协调记录和集成分支基线，再安排现在就能开始的票 |
| 重复启动、中断恢复或接手 | 先核对原协调者、还在跑的实施者、worktree、合入 commit 和验证记录，不重复派工 |
| 单节点任务图或没有 delegation 能力 | 串行做完，照样保留认领、合入和验证要求，不硬开多余 worktree |

进入实施或恢复前读取 [编排与恢复](orchestration.md)。只有用户要求 test-first、风险需要回归测试或现有测试需要扩展时，读取 [行为验证](testing.md)；TDD 不独立成技能，也不强制用于每张票。

实际委派前读取父技能（`think`）目录下的 `references/delegation-budget.md`，按任务难度与风险选择宿主和授权允许的单次参数；不因配置了预算就获得委派权限。

先读取项目已有 `AGENTS.md`、相关 docs 和 tracker 映射，沿用领域术语、验证入口和已有批准。缺少 tracker 配置时用本地 Markdown 与协调记录，不要求 setup。缺少已批准范围或可验收票据时，指出最小缺口；不把普通代码请求自行扩展成任务图编排。

## 实施流程

1. **核对批准与当前状态**：读完整规格、票据和相关评论，确认批准范围、已定接口、测试边界、分支与 dirty 文件归属。重复启动按 [编排与恢复](orchestration.md) 接续现有执行；同一任务已有实施授权时不重复批准。
2. **找出当前可开始的票**：维护唯一协调记录，校验 ID、依赖和环路；只有前置依赖全部合入并验证通过、还没人认领的票才能开始。使用父技能（`think`）目录附带的 `scripts/task_graph.py` 检查记录；脚本路径从已加载技能根目录解析，独立安装和 Desktop 合包都使用附带脚本，不从目标项目找同名程序。
3. **认领与派工**：先记下 owner、票 ID、基线 commit 和共享文件归属，再自己动手或委派出去。有条件且获准并行时，让每个并行实施者从集成分支拉出独立分支或 worktree，只交给他规格、票据、接口和验证路径。同一份共享文件必须指定唯一 owner 或串行改，别等冲突了再救火。
4. **验收单票提交**：实施者交回改动说明、commit、自测结果和限制；`done` 只说明代码交上来待合入。核对它是不是基于正确的集成分支、没改出票外范围、必要检查过了；基线太旧按恢复规则同步，别乱 reset 来源不明的改动。
5. **串行合入再验证**：由唯一的 merger 角色把单票合进集成分支，记下合入 commit；在合入后的真实代码上把本票和受影响下游的必要检查跑一遍，全过才标 `verified`，再放行下一批票。合入冲突、测试挂了或证据失效就先冻住受影响下游，修好重验，不让“写完了”直接跨过集成门槛。
6. **整体验收并收尾**：所有票过完，验证最终集成行为和项目必跑检查，按项目审查习惯扫一遍完整 diff 并把发现的问题修掉。只做本任务明确授权的 push、PR、关票这些外部动作，做完再核对一遍实际状态；清理只动协调记录里记着的任务 worktree 且确认没有未保存修改，不然留着现场把位置告诉用户。

每轮推进节奏变化都由同一个协调者接着管，一个实施者做完或一票合入后直接安排下一批，别每步都另起一套新协调会话。

## 硬性规则

- 单票 `done`、代码合入、集成 `verified`、tracker 关闭是四件不同的事；只有集成验证通过才能解锁下游。
- 一次任务图只有一个活跃协调者和一个串行 merger；角色可以由同一 agent 承担，没有并行能力时直接串行做。
- worktree 创建、分支基线和文件归属以实际 Git 状态为准；不 reset、覆盖或删除来源不明的改动和目录。
- 已授权范围内持续推进；新范围、不可逆操作或没授权的外部动作遵循本任务授权边界，不把 tracker 配置当授权。
- 协调记录用来记事实、证据位置和断点；验证脚本只能检查记录格式对不对，只改状态标签不算跑通，必须看真实运行和验证结果。
- 不自动调用其他技能，不为套流程强制并行、全量测试或创建 PR。
- 实施者编写 TypeScript 时遵循父技能（`think`）目录下的 `references/typescript-style.md`。项目已有 lint 和当前文件的写法优先。

## 常见误区

| 情况 | 规则 |
|---|---|
| 执行者报告完成就派下游 | 先串行合入、运行必要验证，再写 `verified` |
| tracker 已关闭但没有集成证据 | 读回代码与验证，不能据此满足 blocking |
| 两票改同一生成文件或 lockfile | 指定单一 owner，其他票交付源改动；合入后统一生成与验证 |
| 恢复时又创建一批相同执行者 | 先核对 owner 和活跃派工，接续或明确移交后再认领 |
| 一张小票也开多个 worktree | 用单节点串行路径，保留验收与集成记录即可 |

## 输出

- **交付**：规格、集成分支与最终 commit；已合入并验证的票。
- **证据**：本票验证、最终集成验证及未覆盖条件，区分执行者结果与合入后结果。
- **tracker**：实际更新/关闭/PR 状态与读回；没有授权的动作仍列为待办。
- **恢复**：未完成票、owner、阻塞、保留 worktree 和下一次应接续的位置。
