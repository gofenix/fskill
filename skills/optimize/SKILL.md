# Optimize: 让指标改善经得起验证

首行内联带上 🥷，不要单独起段。

在约定预算内寻找有证据的指标改善，保留通过回归门禁的改动，交付基线、实验轨迹和最终收益；没有可测收益也是有效结论。

## 调用边界

首次进入本技能时，须由用户显式输入 `/optimize`、`$optimize`、`调用 fskill 的 optimize`、`用 fskill optimize skill`、`invoke fskill optimize`、`use fskill optimize skill`，或 Desktop 根分发器已从 `/fskill optimize` 选中本技能。同一任务中的回答、补充、纠正和继续请求沿用已显式调用的技能，无需每轮重复命令；新任务或切换到其他技能仍需显式调用。若宿主仅因语义相似自动加载本技能，不应用下文流程，按普通 Agent 请求继续处理。

## 交付约定

- 目标: 用户知道哪些改动带来了可信收益、付出了什么成本，以及哪些行为和平台尚未覆盖。
- 完成条件: 本轮停止原因明确，每个已执行实验都有测量与回归结论；保留改动在最终有效版本上复核，目标未达到或证据不足时如实说明。
- 依据: 用户目标与预算、当前代码和工作区、代表性工作负载、测量入口与配置、实际运行数据、必要 profile 和回归证据。
- 交付形式: 指标与目标、基线到最终结果、保留与撤回的实验、证据路径、回归状态、停止原因及剩余缺口。

## 模式选择

| 当前任务 | 工作重点 |
|---|---|
| 开始持续改善一个已定指标 | 确定实验契约，校核测量并建立基线 |
| 继续已有优化或接手实验 | 读回轨迹、代码与测量条件，确认哪些结果仍有效 |
| 现有数字不能支撑下一轮决策 | 先校核工作负载、完成边界与噪声，暂不叠加产品改动 |

异常或回归的根因定位、一次性设计不确定性实验各有边界；普通任务按原请求处理，不自动切换其他 fskill 技能。用户仅要分析或建议时保持只读；已有本任务实施授权时继续范围内实验，不重复确认。

## 优化流程

1. **限定实验契约**：读取目标入口、相关代码、项目指令和已有实验，核对分支、HEAD 与含 untracked 的工作区状态。写明主指标、单位、改善方向、目标、代表性工作负载、正确性及其他回归门禁、时间或资源预算和停止条件。能从项目确认的事实直接查；只有会改变目标或授权范围的未决取舍才问用户。
2. **证明测量有效**：在建立基线或测量条件变化时读取 [测量与证据](references/measurement.md)。确认计量覆盖实际完成的目标工作、输出正确且错误可见，用有区分力的样本或受控扰动检验敏感性，再冻结本轮测量条件。记录基线分布与回归门禁结果；不把既有失败记为本轮通过。完成条件是测量可重复、覆盖范围和误差已说明，基线足以支持后续比较；否则交付测量缺口，先修正已授权的测量资产。
3. **选择可证伪假设**：进入实验循环或恢复时读取 [实验与恢复](references/experiments.md)。用代码、profile 或评测失败样本解释具体机制，说明预期变化、反证和最小改动。优先选择收益潜力与验证成本相称的假设，不靠排列优化技巧凑轮数。
4. **实验并裁决**：每次隔离一个假设，在可比条件下测量并运行回归门禁，再决定保留、撤回或证据不足。记录失败与无收益实验；仅撤回本轮自己引入且归属明确的实验改动，保护用户工作。完成条件是当前实验已有可核查结论与明确代码状态，才在这条结果之上继续下一轮。
5. **复核并停止**：独立复核最终保留组合相对原始基线的收益和回归，避免把多次试探中最好的噪声当改进。目标达到、预算耗尽、剩余假设收益不足或遇到不能安全推进的阻塞时停止，分别报告结果；不通过降低目标、放宽门禁或隐藏失败结束任务。

持续优化不等于无限运行。未获跨会话调度授权时，本轮预算和宿主能力就是执行边界；恢复位置可以交付，后台调度不能凭意图自行创建。

## 硬性规则

- 指标收益以同一有效测量协议下的实际结果为准，代码阅读、单次最快值、子任务自述和只编译成功都不能证明改善。
- 冻结的测量方法或验收条件需要改变时，按测量参考重建可比基线；不能把修改判据后得到的数字拼接成旧实验收益。
- 正确性与已定回归门禁优先于主指标。无法覆盖真实生产条件、平台或工作负载时，缩小结论并说明限制，不推断普遍收益。
- 沿用项目现有 harness、工具与日志；需要可重复能力时才补最小 helper，不为套流程创建测试框架、决策系统或脚本。
- 实施、外部压测、付费评测、数据写入、委派、commit、push、PR 和调度分别遵循本任务已有授权，不因优化目标自动获得权限或扩大范围。
- 不要求固定实验次数、每轮提交、特定模型或并发规模；验证与重复投入服从噪声、风险、预算和项目要求。

## 常见误区

| 情况 | 规则 |
|---|---|
| 速度提高但完成量下降或错误变多 | 先按真实完成与正确性判定测量有效性，再讨论收益 |
| 改了 harness、数据或评分规则后数字更好 | 重跑两侧建立新基线，保留旧结论的适用范围 |
| 连续几轮没有可测收益 | 回看限制因素或失败样本，预算内换假设；收益不足时明确停止 |
| 想保留“可能有用”的改动 | 未越过噪声或门禁未通过就不计为收益，按实验参考处理代码状态 |
| 只在一个平台或微基准上通过 | 结论限于该条件，补相关端到端证据或明确缺口 |
| 评测分数提升就套性能瓶颈清单 | 按样本、评分、随机性与独立确认判断，不强找 CPU 或 I/O 限制 |

## 输出

先给“有可测收益 / 无可测差异 / 退化 / 证据不足”的结论，再简洁列出：

- **指标**：目标、单位、工作负载与测量条件，基线到最终结果及重复次数和分布。
- **实验**：保留、撤回及证据不足的假设，实际改动与轨迹位置。
- **回归**：最终版本运行过的门禁、已有失败和未覆盖的平台或行为。
- **停止**：达到目标、预算耗尽、收益不足或具体阻塞，未达目标不写成完成优化。
- **后续**：只有仍值得继续时，给最有价值的下一假设和恢复位置。
