# 测量与证据

建立基线、选择比较方法或测量条件变化时读取。它负责判断数字能否支撑结论；实验的保留、撤回与恢复由 [实验与恢复](experiments.md) 负责。

## 明确数字在声称什么

先写出要验证的主张，例如“同一导出流程在代表性数据上的完成延时下降”，再读取实际测量入口，确认计时、计数和忽略的部分。记录能够复跑的条件：

| 条件 | 需要固定或说明的内容 |
|---|---|
| 工作负载 | 数据规模与分布、历史和初始状态、并发、操作序列，以及为什么代表目标使用 |
| 实际工作 | 请求、记录、字节或评测样本的完成数，输出正确性与失败、超时、重试数 |
| 测量边界 | 起止信号、单位、分母，启动/预热、异步完成与持久化是否计入 |
| 运行环境 | 版本与 revision、构建和运行配置、硬件/平台、共享负载及相关外部服务 |
| 测量方法 | harness 与数据版本、命令、必要配置、统计方式和原始结果位置 |

计量结束应对应用户等待的实际完成信号：生成器被消费、异步结果被等待、请求到达目标服务，写入按契约完成。发出请求数、文件存在或进程退出不能自动代表正确完成。输出检查观察实际内容与约定状态，不能只数存在的对象。

先检查工作量和错误数，再比较速度、成本或得分。快拒绝、漏做、提前超时、未等待、死代码消除和只命中缓存，都可能生成漂亮数字；缓存本来就是目标使用的一部分时，明确命中率和冷暖范围，不把它直接视为无效。

## 证明测量有区分力

从目标机制选择预期存在差异的真实样本或受控扰动，写明预期观察，再实际运行。数据规模、历史、状态和并发只改变会影响该机制的维度，不为了凑矩阵遍历所有组合。

如果观察没有区分预期情况，先检查它们是否本就等价、计量边界是否正确、噪声是否掩盖差异。测量尚不能辨别目标变化时，不用它裁决产品实验；修正输入或方法后重建基线。敏感性证明支持这个判别能力，不证明所有场景都已覆盖。

## 性能与成本指标

按实际交付条件比较：适用的生产构建、优化与运行标志、依赖版本、连接池、索引、事务与批处理、缓存及初始状态。启动延时和稳定吞吐的预热处理可能不同，按主张决定并记录；不要消掉用户确实承担的初始化成本。

比较实现时，各侧应采用有依据且现实可用的配置。若实验改变的就是配置，保持其他条件一致并报告配置收益，不能把它表述为实现更优；评估采用方案时，只用明显未调优的一侧作对手不足以支持选型结论。

为性能机制收集适用的 profile、进程/系统 counters 或 I/O 证据，并映射到源码与实际工作。检查负载发生器、客户端或外部服务是否先饱和；被它们限制的数字不能归因到目标实现。**诊断采样与正式计时分开运行**，避免把 profiler、trace 或重型日志的成本混进比较。

用数量级检查主张是否可能：吞吐所需字节量与可用带宽、计算量与核数、收益与被改变部分的端到端占比是否相容。移除占总延时 10% 的部分，理想情况下总延时最多下降 10%；延时下降和吞吐提升不是同一种百分比。超出合理上限时先查工作是否漏做、缓存或计量是否变化，不能直接宣布突破。

微基准只能说明所测片段。需要声称用户收益时，同时覆盖真实端到端路径，说明片段占比；没有证据的限制因素标为假设。重复数据能证明指定条件下存在差异，未验证的机制不能写成已确认根因。

成本比较使用相同有效完成量和质量要求，说明价格、资源或调用数的来源及未计入成本。时间、内存、费用或吞吐之间的取舍由已定回归门禁约束，不把转移成本写成消除成本。

## 评测分数

评测的限制来自任务、评分与抽样有效性，不要求逐项套用资源瓶颈检查。固定任务分布、样本与评分版本、模型和运行配置；记录完整分母、失败、超时和重试的处理方式，避免只统计成功或有利样本。

评分应来自独立规则、已确认样例或适当的评审过程，不能用待测输出自行定义成功。主观评审适合时隐藏变体身份、保持同一评价标准，并保存可复核的输出与裁决；关键词保留、模型自述或评分器自身变化不能代替目标行为改善。

用相同样本或配对随机条件比较两侧，区分任务之间的差异与同任务运行波动。反复据开发样本挑选方案后，用未参与选择的样本或独立确认运行复核；没有这样的证据时，把结论限定为当前样本，不能宣称泛化。覆盖哪些模型、平台或任务类别沿用本轮目标与预算，不默认全量评测。

## 重复、噪声与报告

重复量根据预期效应、观察波动、运行成本和结论风险选择；先声明接受判据，不固定“一次足够”或“必须五次”。使用项目已有统计方法，保留各次数据和适当的中心值、分布或不确定性。差异接近噪声时增加证据或报告无可测差异/证据不足，不只挑最快值或最好得分。

条件允许时交错或随机安排 A/B，避免预热、缓存、系统负载和环境漂移持续偏向一侧。每次恢复可比初始状态，防止上一运行污染下一运行；无法隔离外部负载或无法交错时，明确混杂因素及它如何限制结论。

用户明确只要粗估时，可以交付一次有效运行并标为粗估，仍检查实际完成工作、错误和输出；它不承担实验保留或方案选型的证据强度。严肃比较保留 run 数、分布、工作量与错误、环境和原始记录，最终结果绑定实际 revision 与测量版本。不能完成关键检查时，说明证据不足和最小补证路径。
