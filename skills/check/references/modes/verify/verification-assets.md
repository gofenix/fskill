# 验证资产约定

建立或维护资产时读取。指南面向第一次接手项目的 Agent，命令与判据从目标项目发现，不留下虚构控制器、未核实选择器或待填步骤。

## 发现真实表面

先找用户实际使用的 UI、CLI/TUI、HTTP 服务或库公开 API；一个项目有多个表面时明确本轮支持范围。沿项目文档和现有测试查找启动命令、构建方式、认证、种子数据、驱动入口与可观察结果。浏览器、PTY、HTTP 或平台控制工具按实际表面选择，项目已有 harness 与可用宿主能力优先；用户明确限定工具或切换条件时遵守该边界，不因不可用而绕过限制。

查明端口、数据目录、账号和会话是否可隔离，以及谁拥有运行实例。用户明确允许复用已有实例时说明其边界；否则建立本轮隔离实例。不能隔离的共享实例只由一个协调者驱动，不把源码读取的并行度带到现场操作。

## 资产必须回答的问题

沿用项目已有章节和命令，无需另造同名接口，但应覆盖以下约定。

| 部分 | 指南需写明的内容与可观察完成条件 |
|---|---|
| Launch | 确切启动或构建命令、环境与数据输入、就绪信号、实例标识和停止方式。长驻服务保留实例；短命 CLI/TUI 按每次操作创建隔离会话，不硬套服务器模型。启动失败必须可见。 |
| Doctor | 只读确认当前实例值得操作：目标应用、实际运行 revision/build、端口或会话归属、账号/工作区、数据集、认证和必要功能状态。依据项目可取得的真实标记，无法确认的字段列为缺口；只有进程或端口存在不能确认身份。 |
| Drive | 从用户入口到结果的真实操作、稳定句柄、所需前置和重置方法。优先公开命令、API、角色、可访问名称和稳定属性，不依赖动态 CSS、子节点序号或旧截图坐标。以可观察完成信号推进。 |
| Evidence | 正确状态与错误状态的判别点、需要捕获的操作和结果、业务副作用的交叉验证、产物位置与保留期限。每份证明能对应功能/入口、实例、版本和环境。 |
| Cleanup | 记录本轮创建的进程、会话、数据与临时资源，只清理这些资源；复用实例只清本轮残留。按精确归属停止，不按进程名批量杀。证据放在清理范围外，并在清理后实际确认仍可读取。 |

每次首次驱动、每个新建短命会话以及异常操作后先做 Doctor。进程健康却界面卡住时，恢复已知状态或重启本轮实例；不能凭一次健康检查继续猜测。每次失败迭代都清理自己的残留，不等最终成功才清理。

## 功能地图

沿用已有功能索引；没有时，为批准范围建立最小索引和功能条目。地图以用户视角组织，可按功能拆文件，也可沿用项目现有单文件结构，不固定文件数量。

每个功能条目应能回答：

- **行为与入口**：用户要完成什么，如何从菜单、快捷键、命令或公开 API 到达；列出不同入口，避免只覆盖最方便的一条。
- **前置与重置**：账号、权限、fixture、flags、依赖服务及适用平台；如何回到独立的初始状态。
- **操作与判据**：已有 harness 的确切动作、稳定句柄、关键正常与失败状态，以及什么可观察结果算通过。只列与此功能相关的状态，不把所有状态名机械填满。
- **证据与交叉验证**：操作过程、结果、必要的只读第二视角及其产物位置；写入行为可通过重新打开、读取 API 或文件等确认持久结果。
- **限制**：错误表面、已知陷阱和不可用前置；按尝试的入口报告，不能拿另一条路径的成功替代。

索引能定位每项功能及其适用范围。内部函数和代码行号只作为本轮发现线索，不作为地图的长期行为契约。

## 证明真实行为

通过实际使用表面触发行为，状态查询只作只读交叉验证。准备隔离 fixture、权限或测试服务可以设置前置，但不能用内部 setter、隐藏端点、直接写存储或注入 DOM 制造要证明的结果。替身只在已有生产边界隔离外部系统时使用，说明未验证的真实集成。

截图需体现应用身份和判别状态，必要时保存操作前后或录屏；CLI 保存输入、stdout、stderr、退出码，服务保存请求、响应及相关副作用。证据形式跟随行为，不强制所有表面截图或录视频。涉及写入时检查保存后的实际状态；涉及禁止副作用时实际观察其边界，不能只相信 `dry-run` 或 `test` 名称。

替代环境确实能检验同一机制时，可提供明确标注的替代证据；如果缺失的 OS、账号或外部状态就是缺陷的一部分，它仍是原场景的缺口。不可达项记录尝试的路由与具体前置，不计为通过。

必要 helper 只封装可重复且容易失真的具体操作，写明运行条件、输入输出、失败信号与调用方式，并实际运行。它应随项目资产自包含，不依赖个人缓存或 fskill 源码目录。原始证据默认进入项目既有 artifact 区域或隔离临时位置，避免把凭据、用户数据和一次性运行产物提交到源码。
