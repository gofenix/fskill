# 维护验证资产

在已有验证指南、harness 或功能地图上使用；运行约定以同目录的验证资产约定为准。维护的目标是保持可复跑能力，修正资产漂移，不接管产品修复。

## 确定目标与覆盖范围

定位实际被项目导航引用的资产及其自有 helper。多个候选无法从任务和导航确定时，只澄清目标；没有可维护资产时说明缺口，不凭空声称维护完成。

默认检查已有地图的全范围；用户限定部分时沿用，并在结论中写明其余未检查。核对索引与条目，合并重复、修正缺失或失效链接。每个范围内功能和列出的不同入口都保留源码核对与现场结果；可合并等价操作以减少启动次数，但不能把一个入口通过记到未尝试的另一入口。

## 维护流程

1. **源码核对**：沿用户入口追当前实现、公开契约和相关版本变化，判断地图描述是否仍成立。需要并行读取时可委派有界、只读问题，返回源码证据与一条现场操作建议；子任务不驱动共享实例，不修改文件。近期新增用户表面只有具体源码或文档证据时才列为地图遗漏。
2. **协调现场覆盖**：合并可复用的操作前置，由协调者按资产的 Launch 模型运行，并按验证资产约定执行身份检查、操作、证据和失败清理。源码看起来一致也不能跳过现场。为每项记录实际入口、预期、观察与证据，标明通过、失败或具体前置未满足。
3. **分流发现**：需求或版本变化已证明的描述错误属于文档漂移；行为正常但 harness 无法操作属于 harness 缺口；违背预期的应用行为属于产品回归。只修前两类。意图不明时保留差异与证据，不按当前错误输出改写期望。
4. **修正并复跑**：仅修改验证资产和其拥有的 helper，保持项目既有格式与导航。修正影响启动、Doctor 或驱动条件时，重建受影响状态，再从真实入口重跑相关功能；文档里的命令变化同样需要实际验证。不能因文本或链接检查通过就把未跑功能转为通过。
5. **收尾读回**：完成最后一次修正复跑后再最终清理，确认没有本轮遗留实例或临时数据，并读回保留证据。回读最终资产，交付覆盖与缺口；运行记录留在证据位置，不自动创建 PR 或提交报告。

资产漂移使 Doctor 失败时，在资产编辑范围内修正，再以修正后的条件有界重试；若是产品、权限或环境限制，写清阻塞阶段，不无限重启或扩大修改范围。

## 结果判定

| 结果 | 条件 |
|---|---|
| 无需修正 | 本轮范围源码与现场覆盖完整，没有值得改的资产漂移；附证据与清理结果 |
| 已修正 | 资产变更已从实际入口复跑，逐项覆盖与剩余缺口准确；不等于产品全部通过 |
| 存在缺口 | 前置未满足、产品回归或修正未获证明；列出功能、入口、阶段、证据和最小下一步 |

结果可同时包含已修正项和缺口。只有范围内所有必要操作都有有效通过证据，才可称该范围验证通过；源码检查、跳过、不可达和一半前后证据均不能替代。
