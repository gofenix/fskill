# 审查高频失真模式

只针对 diff 实际命中的类别核对；若同根因反复出现在历史事故中，对照 [事故台账](incident-ledger.md) 将防护落到结构或检查器。

- **安全前提未证实**：先把结论最依赖的前提写出来（例如“所有调用方已迁移”“密钥不会入库”），沿真实消费者、依赖解析版本与调用顺序查证，搜索未覆盖的部分标未知。
- **非原子替换与未捕获信号**：向已有用户路径写入（`>`、`curl -o`、`tee`）必须写同目录临时文件 + `EXIT/INT/TERM` 清理 + 原子替换，并校验重复执行与失败中断后不损毁原文件。
- **破坏性匹配范围过宽**：删除、清理、覆盖或遍历逻辑的保护必须在底层操作内部生效，授权必须绑定精确标识符或精确路径，绝不用显示名、前缀或模糊匹配作为删除依据。
- **重复推导与历史一致化陷阱**：同一资格/排序/计数规则出现两份独立实现（如摘要 vs 列表）必然漂移，要求收敛单一来源；“统一例外”前先查 `git log`/注释，确认例外是不是已知 bug 防护。
- **测试未命中真路 & 门槛被暗自放宽**：只测从不执行的辅助函数或源码字面量不算覆盖（遵循「行为测试」先红后绿）；发现提高容差、扩 allowlist 或跳过检查时，必须核对原失败证据与真实需求而非只看修改者的新绿灯。
- **从未发布功能带着迁移代码**：对比最近 tag，首次出现于当前分支的配置键或 schema 绝不应自带迁移或版本兼容层。
- **固定等待代替可观察完成 & 依赖变更**：指出用 `sleep`/`setTimeout` 等异步完成的问题；依赖或版本锁改动需核对完整 diff 与导入链是否真进入分发产物。
- **修订与重审绑定 `revision`**：rebase 或小修后，涉及共享边界或底座函数的语义变化不能凭旧的 `patch-id` 复用历史审查绿灯。
