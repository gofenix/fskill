# 发布产物模式

`/check` 使用本地平台产物准备 GitHub release，或用户提到打包、macOS 安装包、APK/AAB、公证、发布附件上传时，读取此参考。

## 命令选择

按以下顺序选择命令：

1. 同一任务中仍有效的用户指定命令或已约定计划中的命令。
2. 项目公开上下文：README、AGENTS/CLAUDE、Makefile、package scripts、Gradle/Fastlane/Xcode/Electron/Tauri 配置，以及 CI 发布工作流。
3. 从 manifest 推导的候选命令；执行完整发布构建前，先交用户确认。
4. 没有明确命令时，一次问清预期构建命令、变体和产物类型。

不要硬编码个人路径、签名材料位置、私有应用名称或特定机器配置。

## 通用检查

声称已就绪或已交付前，收集以下证据：

| 检查项 | 证据 |
|---|---|
| 构建命令 | 确切命令、退出状态，以及命令来自用户还是项目公开上下文 |
| 版本 | 项目版本、平台 manifest 版本、Git tag、发布标题和附件命名一致 |
| 产物 | 路径、类型、字节大小和 SHA-256 哈希 |
| 签名 | 已签名或未签名状态，以及必需凭据是否存在；不打印秘密值 |
| 上传 | GitHub release URL、附件名、可获得的大小和哈希，以及上传后的远端回读 |

发布附件已存在时，未经用户明确授权，不覆盖、删除或重新上传。询问是保留现有附件、重命名新附件、删除后重新上传，还是创建新版本。

## macOS 检查

对于 `.dmg`、`.zip`、`.pkg` 或应用包：

- 从项目 manifest 或构建输出确认应用版本和构建号。
- 项目提供 bundle identifier 时，确认其值。
- 有可用工具时，用项目支持的命令或平台工具确认签名状态。
- 项目要求公证分发时，确认公证和公证票据装订状态。
- 上传前记录最终分发产物的路径、字节大小和 SHA-256 哈希。

缺少签名证书、Apple 凭据或公证凭据会阻塞交付。只报告缺失类别，不要求用户把秘密粘贴到聊天中。

## Android 检查

对于 `.apk` 或 `.aab` 产物：

- 从 Gradle 输出、manifest 或项目文档确认 `versionName`、`versionCode`、variant 和 flavor。
- 确认产物是 debug 还是 release、已签名还是未签名。
- 确认签名配置存在，不打印 keystore 路径、别名、密码或 token。
- 优先使用项目定义的 Gradle/Fastlane/CI 命令，而非推测的 `assembleRelease` 或 `bundleRelease`。
- 上传前记录最终产物路径、字节大小和 SHA-256 哈希。

缺少 keystore 材料或签名凭据会阻塞交付。不要编造发布变体；除非用户明确要求未签名的诊断产物，否则不要上传未签名的发布产物。

## 输出证据

发布产物模式的最终输出必须包含：

- 构建命令及验证命令的结果。
- 产物路径、类型、大小和 SHA-256 哈希。
- 版本、tag 和发布附件的一致性结论。
- 已上传时，给出 GitHub release URL 和远端附件回读结果。
- 阻止构建、签名、上传或远端验证的任何阻塞项。
