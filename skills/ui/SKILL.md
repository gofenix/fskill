# Design: 带着判断力做界面

首行内联带上 🥷，不要单独起段。

## 交付约定

- 目标: 从需求形成可用的新界面，或改善现有产品的具体体验，具备明确的视觉方向。
- 完成条件: 实现任务的核心流程可操作，真实渲染已覆盖相关屏幕与状态；仅设计或审查时，交付可执行的方案或诊断，说明验证缺口。
- 依据: 当前需求、运行界面、截图、源组件、设计 token、可访问性约束和用户参考。
- 交付形式: 可运行的界面与效果证据，或用户要求的设计方案、视觉审查；说明设计选择解决了什么问题。

**输出语言规则**：本技能的所有输出都不用 em-dash，改用逗号、冒号或句号。

## 长期上下文预检

先读取 [长期上下文预检](references/durable-context.md)。可选读取，只作为背景。对 `/ui` 来说，旧记忆可以提供视觉偏好、设计原则和成熟交互模式；当前截图、渲染结果、源码、设计 token 和用户反馈优先于旧记忆。

## 调用边界

首次进入本技能时，须由用户显式输入 `/ui`、`$ui`、`调用 fskill 的 ui`、`用 fskill ui skill`、`invoke fskill ui`、`use fskill ui skill`，或 Desktop 根分发器已从 `/fskill ui` 选中本技能，或当前会话里用户已进入 `/f-mode` 且 f-mode 点名了本技能。同一任务中的回答、补充、纠正和继续请求沿用已显式调用的技能，无需每轮重复命令；f-mode 关闭时，新任务或切换技能仍需显式调用；f-mode 开启时可由 f-mode 按当前目标重新选择。若宿主仅因语义相似自动加载本技能，不应用下文流程，按普通 Agent 请求继续处理。

不用于后端逻辑或数据流水线。文档、PPT、简历、长报告、分页 PDF 建议走 Kami（`tw93/Kami`）等文档设计系统。App、网页、组件和屏幕 UI 由本技能处理。

## 场景选择

按实际界面与任务选择，只读对应参考。缺少设计文档不代表没有现有产品。

| 现场与目标 | 按需读取 |
|---|---|
| 只有需求、没有 UI，或新建独立界面 | [新产品设计](references/design-new-product.md)：需求、核心流程、代表页面、可交互主流程 |
| 已有产品的评审、打磨、截图迭代或局部快修 | [现有产品优化](references/design-refinement.md)：基线、分层诊断、按影响修正、前后验证 |
| 明确要求整体改版或替换视觉方向 | 先读现有产品优化，保留产品事实与功能约束，再用新产品设计探索替换方向 |

涉及手势、抽屉、拖拽、可中断过渡或动效调优时，再读 [交互与动效](references/design-motion.md)。官网、营销页的艺术方向在新产品设计参考中，工具产品默认围绕核心任务设计。

用户说“很傻”“很怪”“突兀”“不协调”“不和谐”时，按现有产品的截图迭代处理；证据证明是回归或渲染错误时，可建议显式调用 `/hunt`，不自动切换技能。

## 范围与项目上下文

- 仅设计或审查时交付方案、诊断与建议，不修改目标项目或持久配置；已有明确修复授权时，完成范围内修改和验证，不重复索要批准。只澄清会改变范围、方向或产品行为的缺口。
- 先读需求和项目证据，说明必要假设，不把方向确认变成固定问卷。现有设计系统、组件、图标库和平台惯例优先于参考中的风格偏好。
- 产品事实与视觉决策分开维护：用户、任务、约束属于产品事实；排印、配色、布局、组件与动效属于设计决策。优先复用现有文档，确需持久化且在授权范围内时才补充，`PRODUCT.md`、`DESIGN.md` 是可选载体，不是开工前置条件。

## 真实验收

实现后操作核心任务和受影响状态，检查真实渲染。网页覆盖相关断点两侧；原生 app 检查最小宽度、最小高度、两者组合和正常尺寸。按影响覆盖长中文、长英文、按钮标签与加载、空、错误等状态，测试尺寸不意味着新增布局分支。

截图证明布局，交互需实际操作；动效需连续过程证据。无法运行时说明具体缺口与已检查范围，不把编译通过或源码推测写成视觉验收通过。修复证据出现新问题时再迭代，不无限自我打磨。

## 硬性规则

- 以主体或场景承载视觉方向的页面要使用相关真实视觉资产，不用纯 SVG/渐变假装主题；工具界面不为装饰硬加图片。
- 3D 必须用 Three.js，主场景全幅或无框，完成前用截图和 canvas pixel 检查非空。
- 不做卡片套卡片，不把页面 section 做成漂浮卡。
- 不用装饰性 orb、gradient orb、bokeh blob。
- 文本不得挤出按钮、卡片或容器；移动和桌面都要检查。
- 不用 viewport width 直接缩放字号，letter spacing 默认 0。
- 不做单一色相大面积 UI，尤其避免整页紫、蓝紫、米色、深蓝、棕橙一把梭。

## 输出

完成后简洁说明设计选择及其解决的问题、已验证的流程与屏幕／状态，以及仍需判断或补证的具体项。评审按影响排序给建议，实现给出真实效果证据。
