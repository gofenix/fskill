# 设计参考

这是 `/ui` 的控件、布局与视觉参考。新建与优化工作流由入口按场景选择，需要设计细节时读取本文件。

## 设计前提与控件

- 现有设计系统优先。读组件、设计变量、图标库和页面惯例，不要凭空发明风格。
- 工具产品第一屏应直接呈现工作台或核心任务体验，不是营销介绍，除非用户明确要落地页。
- 工具图标优先项目已有图标库，无约定时用 lucide；纯图标按钮配 tooltip 或可访问标签，不熟悉的图标同时给文字标签。

## 布局与视觉规则

- 固定格式元素要有稳定尺寸：画板、网格、工具栏、图标按钮、计数器、图块。
- 不做卡片套卡片；页面区块采用全宽分区或无框布局，卡片只用于重复项、模态框或真正需要边框的工具。
- 文本不能覆盖前后内容，长词不能挤出容器。默认自然换行；孤行先检查容器宽度和强制断行，不为凑行数删除有效信息、缩小字号或收窄容器。仅在保留含义和限定条件时精简重复，标题平衡需检查实际容器及语言。
- 不用视口宽度缩放字号；正文和工具界面字间距默认 0，展示标题按实际字体、字号与中英文内容验证后可调。
- 限制单一色相大面积使用，尤其避免整页紫/蓝紫、米色、深蓝、棕橙。
- 图像要揭示真实产品、地点、对象、状态或玩法，不用模糊、带素材库感的氛围图。

## 首屏主视觉规则

只有真正需要落地页时才做首屏主视觉，并用相关真实图片、生成位图或沉浸式交互背景；优先按产品内容和结构决定布局与第一屏节奏，需要延续阅读流时再露出一部分下一区块。

品牌、产品、地点、人物页面，第一屏必须明确显示主体，不要只放在导航小字里。

## 3D 规则

Web 3D 优先用 Three.js（项目已有 3D 栈或原生平台沿用既有框架）。主 3D 场景全幅或无框，不放在装饰卡片里。完成前用浏览器截图和画布像素检查：非空、构图正确、会动或可交互、资源加载成功、桌面和移动都不重叠。

## 改版范围

已有产品的优先级与验证方式见[现有产品优化](design-refinement.md)。明确替换整体方向时，再进入[新产品设计](design-new-product.md)，保留原产品事实、功能和平台约束。
