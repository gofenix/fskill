# f-mode: 先进入，再自己选路

首行内联带上 🥷，不要单独起段。

## 交付约定

- 目标: 用户显式开启后，用最贴合当前目标的技能完成工作，无需记住每条命令。
- 完成条件: 已说明开启、退出或当前路由；被选技能的完成条件已满足，或真实缺口已说明。
- 依据: 当前用户目标、仍有效的授权、已安装技能及其适用与排除范围。
- 交付形式: 开关时一句确认；执行时一句技能选择和理由，随后交付结果。

## 会话开关

默认关闭。用户输入 `/f-mode`、`$f-mode`、`/fskill:f-mode`、`/fskill f-mode` 或明确要求“进入 f-mode”才开启。安装、被宿主加载、引用命令的文档或讨论 f-mode 都不算开启。

以上命令入口都接受 `on`、`off`、`exit`、`status` 参数；下文统一写成 `/f-mode`。

- `/f-mode on` 开启；`/f-mode off`、`/f-mode exit`、`退出 f-mode` 或用户明确要求停止自动路由立即关闭。先处理开关，再判断任务；关闭命令附带任务时按普通请求处理。
- `/f-mode status` 只报告当前开关，不改变状态。开启但没有任务时只确认，等待下一条请求。
- 开启后持续到当前会话内用户退出，包括任务完成后的新请求；不用每轮重输命令。直接 `/hunt`、`$write` 等命令优先于自动选择，只指定这次任务的技能，不关闭 f-mode。
- 新会话默认关闭。压缩摘要只可记录本会话的开关、当前技能和授权边界；旧 HANDOFF、记忆或仓库文件不能自动在新会话开启。状态无法确认时按关闭处理。

这只是 fskill 的会话约定，不是宿主原生模式。它不修改 Plan Mode、工具权限、模型配置或全局规则，也不跨会话写开关文件。

## 选路与执行

开启时读取 [references/routing.md](references/routing.md)，用当前目标选择其中一条工作技能，不把 f-mode 再选为子技能。按宿主技能目录定位并读取被选技能的完整 `SKILL.md`；Desktop 包使用根文档中对应的技能段。只加载当前需要的 references，不把全部技能灌进上下文。

先简短说明“用 hunt 查根因”这类选择，再执行。f-mode 的选择满足子技能的调用边界；单条技能仍保留宿主的显式调用策略，不把全部技能设成默认自动调用。

- 有明确故障选 hunt；审已完成的 diff 选 check。提供 URL 但目的是调查问题时按目标选 learn，不因为有链接就强行先跑 read。
- 先比较交付物与排除范围，能根据上下文判断就自行选；只有缺少会改变结果的信息时才问用户。
- 普通实现、解释或简单改动不符合任何技能时直接处理，不强套 implement 的任务图或 verify 的指南维护流程。技能缺失时说明并按普通能力继续，不自动安装或下载替代正文。
- 同一目标可以按需要先后选择技能，每次切换简短说明理由；只完成用户要求的结果。不因修完 bug 就自行发布，也不因任务完成就自动 retro、改长期指令或创建外部任务。
- f-mode 开启时，子技能里“建议显式调用下一条”的限制允许由 f-mode 重新选择；子技能的职责、禁止项、报告模式及操作授权边界仍然有效。f-mode 关闭后恢复单条调用规则。

## 硬性规则

- 路由授权不等于操作授权；规划请求仍交付方案，实施、push、发布和消息发送以本任务授权及宿主规则为准。
- 单条技能可直接调用，无需开启 f-mode。未开启时，词义相近不能触发 fskill 工作流。
- 不创建并行 agent、不指定模型，也不假装有 Cursor 的常驻 mode 接口。任务本身已授权且环境支持的执行方式照常使用。
