# 工程原则索引

`pstack` 风格原则均为独立技能，模型按场景触发；此处只作速查索引，不复制正文。

| 原则 | 何时重点应用 | 技能名 |
|---|---|---|
| 先减后增 | 准备新增抽象、配置开关、桥接层或重构时 | `p-subtract-before-add` |
| 质疑前提 | 同一卡点连败两次或变通代码比主功能更大时 | `p-attack-the-premise` |
| 先证根因 | 出错、崩溃、回归，动手改代码前 | `p-fix-root-causes` |
| 真实验收 | 声称修复、完成、安装就绪、视觉达标或可发版前 | `p-prove-it-works` |
| 行为测试 | 新增/修改测试、判断断言价值或调整通过门槛时 | `p-test-behavior` |
| 解释数字 | 汇报性能、配额、体积、评测数字或做单假设优化时 | `p-explain-the-number` |
| 结构防复发 | 沉淀验证过的教训，或定义 TypeScript 类型与入口边界时 | `p-encode-in-structure` |
| 边界与单向门 | 改脏仓库、跨单向门动作或处理网页/issue 等不可信输入时 | `p-respect-boundaries` |

原则只在确实改变了本次决策时点一句名字与依据，不为了凑格式全套出场。
