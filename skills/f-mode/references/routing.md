# fskill Skill Resolver

20 个工作技能，加 f-mode 路由和 f-help 帮助入口。默认显式调用 `/name` 或 `$name`，话题相近不会启动流程。显式进入 `/f-mode` 后，当前会话内可按目标自动选技能；`/f-mode off` 退出。单条命令优先，不关闭 f-mode。

## 路由

| 触发 | 技能 |
|------|------|
| 用户显式进入 f-mode，按目标选技能，并按需读取工程原则 | `f-mode` |
| 询问 fskill 用法、该选哪条、模式机制、安装排障或定制 | `f-help` |

## 想清楚

| 触发 | 技能 |
|------|------|
| 把想法收成能执行的计划，包含追问和值不值得做 | `think` |
| 页面、组件、截图审美 | `ui` |
| 一个词或一种行为的边界说不清，而且挡着当前决定 | `domain` |
| 目标会跨多次会话，路线还没清 | `map` |
| 规格已经定了，拆成能单独演示的纵切 | `slice` |
| 用一次性实验验证一个具体假设 | `prototype` |
| 看代码边界该保持、拆开、合并还是加深 | `architect` |

## 做出来

| 触发 | 技能 |
|------|------|
| 按已经批准的任务图实施、合入、验证 | `implement` |
| 已经坏了，先证明根因再修 | `hunt` |
| 指标已经定了，一次只试一个假设 | `optimize` |

## 交出去

| 触发 | 技能 |
|------|------|
| 审 diff、技术方案、合并前、push 前、发布 | `check` |
| 处理 issue 和外部 PR 队列 | `triage` |
| 维护项目的验证指南和操作入口 | `verify` |

## 读和写

| 触发 | 技能 |
|------|------|
| 一份已经给出来的 URL 或 PDF | `read` |
| 陌生领域、一套代码或一串历史决策 | `learn` |
| 改稿、润色、去掉 AI 味 | `write` |

## 下次还能用

| 触发 | 技能 |
|------|------|
| 交出或接回当前会话现场 | `handoff` |
| 把已经验证、还会再犯的教训写回去 | `retro` |
| 查 agent 配置、指令漂移、hooks | `health` |
| 必须人亲手做的配置或迁移 | `wizard` |

## 边界

- 没进入 `/f-mode` 时，下面的表不自动换技能。单条命令仍然直接进入对应技能。
- 上下文装不下走 `handoff`。路线还没清走 `map`。
- 已确认的术语和 ADR 走 `retro`。还在厘清概念走 `domain`。
- 已经坏了走 `hunt`。没有故障、要看 diff 能不能交，走 `check`。
- 方案设计走 `think`。界面走 `ui`。
