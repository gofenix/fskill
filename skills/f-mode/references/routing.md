# fskill Skill Resolver

10 个工作技能，加 f-mode 路由和 f-help 帮助入口。默认显式调用 `/name` 或 `$name`，话题相近不会启动流程。显式进入 `/f-mode` 后，当前会话内可按目标自动选技能；`/f-mode off` 退出。单条命令优先，不关闭 f-mode。更细的做法是选中技能后的模式，不再各占一条命令。

## 路由

| 触发 | 技能 |
|------|------|
| 用户显式进入 f-mode，按目标选技能，并按需读取工程原则 | `f-mode` |
| 询问 fskill 用法、该选哪条、模式机制、安装排障或定制 | `f-help` |
| 只读核对本会话进展、变化、阻塞及仍待用户处理的事项 | `catchup` |

## 想清楚

| 触发 | 技能 |
|------|------|
| 把想法收成能执行的计划，包含追问和值不值得做 | `think` |
| 任务已经给定，校准方法、目标与约束后直接按授权工作 | `think` |
| 一个词或一种行为的边界说不清，而且挡着当前决定 | `think` |
| 目标会跨多次会话，路线还没清 | `think` |
| 规格已经定了，拆成能单独演示的纵切 | `think` |
| 用一次性实验验证一个具体假设 | `think` |
| 看代码边界该保持、拆开、合并还是加深 | `think` |
| 按已经批准的任务图实施、合入、验证。普通代码修改由当前 Agent 直接做 | `think` |

## 找问题

| 触发 | 技能 |
|------|------|
| 已经坏了，先证明根因再修 | `hunt` |
| 指标已经定了，一次只试一个假设 | `hunt` |

## 做检查

| 触发 | 技能 |
|------|------|
| 审 diff、技术方案、合并前、push 前、发布 | `check` |
| 处理 issue 和外部 PR 队列 | `check` |
| 维护项目的验证指南和操作入口 | `check` |

## 界面

| 触发 | 技能 |
|------|------|
| 从需求设计新界面，或评审、打磨现有页面、组件与截图 | `ui` |

## 读和写

| 触发 | 技能 |
|------|------|
| 请求读取、抓取、引用、转换或保存一份 URL 或 PDF | `learn` |
| 陌生领域、一套代码或一串历史决策 | `learn` |
| 改稿、润色、去掉 AI 味 | `write` |

## 下次还能用

| 触发 | 技能 |
|------|------|
| 交出或接回当前会话现场 | `handoff` |
| 把已经验证、还会再犯的教训写回去 | `retro` |
| 查 agent 配置、指令漂移、hooks | `health` |
| 必须人亲手做的配置或迁移 | `health` |

## 边界

- 没进入 `/f-mode` 时，下面的表不自动换技能。单条命令仍然直接进入对应技能。
- 上下文装不下走 `handoff`。路线还没清仍走 `think`。
- 已确认的术语和 ADR 走 `retro`。还在厘清概念走 `think`。
- 已经坏了，或指标已经定了，走 `hunt`。没有故障、要看 diff 能不能交，走 `check`。
- 方案、术语、路线、切片、一次性实验、代码边界、校准后就做、已批准任务图都走 `think`。可交付界面走 `ui`。普通代码修改由当前 Agent 直接做。
- 项目代码体检、队列和可复用验证指南走 `check`。Agent 配置和必须由人完成的迁移走 `health`。
