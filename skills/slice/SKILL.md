# Slice: 把确定规格拆成可交付任务图

首行内联带上 🥷，不要单独起段。

从已经确定的目标和约束出发，让每张票都有可观察的交付、验收依据和真实阻塞关系，后续实施者无需重新猜测范围。

## 调用边界

首次进入本技能时，须由用户显式输入 `/slice`、`$slice`、`调用 fskill 的 slice`、`用 fskill slice skill`、`invoke fskill slice`、`use fskill slice skill`，或 Desktop 根分发器已从 `/fskill slice` 选中本技能。同一任务中的回答、补充、纠正和继续请求沿用已显式调用的技能，无需每轮重复命令；新任务或切换到其他技能仍需显式调用。若宿主仅因语义相似自动加载本技能，不应用下文流程，按普通 Agent 请求继续处理。

## 交付约定

- 目标: 将确定的规格变成可以独立验收、按阻塞关系实施的任务图。
- 完成条件: 规格范围可追溯，每张票都写明行为、验证与阻塞；依赖无缺失、无重复 ID、无环；首批可开始的票和共享文件风险明确。
- 依据: 用户已确定的讨论、规格正文和评论、当前仓库指令、相关代码与测试、现有术语/ADR、tracker 约定。
- 交付形式: 规格指针、逐票契约、阻塞 DAG、可开始的票、最小未决阻塞及实际保存位置；沿用项目 tracker 或本地 Markdown。

## 输入与落点

| 输入情况 | 处理 |
|---|---|
| 已有规格或 issue | 读取完整正文、相关评论和已有子票，补足切片需要的当前代码依据 |
| 讨论已经定案但没有规格 | 按 [规格与票据](references/spec-and-tickets.md) 固化已定内容，保留决定依据 |
| 范围或验收仍有关键歧义 | 只指出会改变切片的最小阻塞；已确定的部分继续整理 |
| 已有任务图需要细化 | 保持既有 ID 和已完成工作，只调整受影响的票与边 |

先读取项目已有 `AGENTS.md`、相关 docs、术语/ADR 和 tracker 映射。没有 tracker 配置也能交付：沿用已有本地目录；没有约定时使用 `.scratch/<feature>/`。不先创建一套 setup 配置，也不因缺少术语或 ADR 文件而中断。

## 切片流程

1. **固定依据与边界**：核对目标、已定接口、范围外事项和外部可观察的测试边界。沿用已经确认或现有适用的边界；只有选择会改变验收或实施范围时才提出最小澄清，不重新开展需求访谈。
2. **找到最窄完整路径**：每张票穿过交付该行为所需的层，完成后可以演示或独立验证。先做一条真实路径，再扩展输入、异常和规模；不强迫每张票都触碰与行为无关的 UI、数据库或 API。
3. **写逐票契约**：按 [规格与票据](references/spec-and-tickets.md) 写 ID、scope、行为验收、verification、blocking、并行文件风险和稳定接口线索。预整理仅在阻塞后续交付时单列，并给它独立验证，避免把顺手重构塞进第一张票。
4. **建立真实阻塞 DAG**：边表示后票不能正确实施或验收的前置条件。共享文件冲突先尝试明确 ownership 或稳定接口；仍无法安全并行时才加顺序约束。检查重复 ID、缺失引用、环路和首批可开始的票，说明真正的关键路径。
5. **核对并落地**：展示每票交付、阻塞和粒度。已有授权覆盖且范围已定时继续保存，不逐票索要批准；仅有分析授权时交付草案。记录任务图是否已获实施批准，但不把拆票请求当成实施授权。外部 tracker 写入按本任务授权执行，写后读回票号、正文和 blocking 映射。

完成切片的条件是所有规格行为都映射到票或明确的范围外事项，且每张票都有独立验收办法。实现方案或测试边界尚未定到足以写票时，报告具体缺口；不要用含糊占位票假装任务图已经可实施。

## 机械迁移

宽范围的同一机械变更使用 **expand–contract**，详见 [规格与票据](references/spec-and-tickets.md)：先增加兼容形式，再按影响范围迁移，最后移除旧形式。每张迁移票都必须可验收；无法独立保持约定验证通过的变更合并为一张票，不把所有失败留给最后的“集成票”。

## 硬性规则

- 切片继承已定规格；新取舍或范围变化要显式标出，不能悄悄代用户决定。
- 一张票交付一个可观察结果，尺寸以单个实施上下文能理解、实现和验证为准，不以文件数或固定票数凑粒度。
- blocking 只记录真实前置；状态标签、票号顺序和共享目录本身不构成依赖。
- 使用稳定的模块、接口和领域名称；当前文件路径可以作为 ownership 与定位线索，标明是当前快照，不把易漂移行号当成契约。
- 沿用项目 tracker、标签和关闭规则；没有映射时本地交付，不擅自新建标签、发布外部 issue 或关闭父票。
- 不自动调用其他技能，不修改产品代码，也不把草案任务图声明为已批准实施。

## 常见误区

| 情况 | 规则 |
|---|---|
| 按“数据库、后端、前端、测试”各开一票 | 改成能跑通的行为切片；仅真实机械迁移采用 expand–contract |
| 所有票都依赖上一票 | 逐边说明阻塞原因，移除纯粹为了排序的边 |
| 票上只写“测试通过” | 写观察入口、输入、预期结果、命令和验证限制 |
| 缺少 tracker 配置 | 保存本地规格和票，不要求先安装或运行 setup 技能 |
| 已确认讨论又变成长篇采访 | 直接综合已有决定，只问会阻塞切片的缺口 |

## 输出

- **规格**：来源、已定范围、测试边界和必要的新规格位置。
- **任务图**：每票 ID、交付、blocked by、验收与验证指针，列出首批可开始的票。
- **并行边界**：共享文件 owner、接口约定和必须串行的部分。
- **状态**：草案或已批准、实际保存/发布位置、读回结果及剩余最小阻塞。
