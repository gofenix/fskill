# 行为测试（Test Behavior）

只会在坏代码上也通过、或者一重构内部结构就崩掉的测试，不是保护网而是负担。

## 触发信号

- 新增回归测试或修补测试断言
- 测试大量断言内部 helper 调用次数、私有状态或重度 mock 返回值
- 准备提高容差、扩充 allowlist、改写失败用例以让流水线变绿

## 原则

1. 测入口行为而非内部路线：尽量从用户或调用方真实的公开入口驱动输入并验证可观察结果；预期值来自需求规格、已知样例或独立规则，不由待测代码反向推导。
2. 先红后绿防假阳：每条新回归测试都要在未修复状态（或临时隔离副本）实跑确认报红，再在修复后变绿；用否定断言（如 `not in`）时，补一个能触发它的正例证明检查真的长着牙齿。
3. 绝不贴着真实使用路径漏网：不要只测永远跑不到的脚本碎片或字面字符串；输入必须经过真实的解析与边界处理。
4. 放宽门槛须重审真需求：只有需求确实变更时才能改预期；若需放宽容差或跳过检查，必须保存原失败证据与原因并按原始目标复核，不凭修改者自己新出的绿灯签收。

## 坏 vs 好

- 坏：直接 mock 掉底层解析函数并断言它被调用一次，结果上线后真实输入格式变化照样崩。
- 好：喂入真实格式片段走完整入口，验证在旧实现上报错且新实现上返回准确状态，并保留一条会触发校验拒绝的反例。
