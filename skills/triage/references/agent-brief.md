# 可接手的行为契约

仅对准备实施的条目使用。沿用原 issue 或项目任务格式，不复制一套彼此漂移的需求文件。

- **问题与结果**：谁在什么场景遇到什么问题，期望可观察行为是什么。
- **当前证据**：版本、复现步骤、现有入口、实际结果和来源；已修复与待验证分开。
- **范围**：接受的行为、明确不包含的内容、需要保留的兼容性与用户工作。
- **验收**：正常路径、关键反例和失败路径；预期来自需求或已确认事实，不从当前实现反推。
- **验证入口**：已有命令、测试接缝、必要环境与尚缺条件。稳定接口定位可保留，易漂移文件行号仅作线索。
- **依赖与权限**：阻塞项、责任人、agent 可执行动作及人必须做的步骤。

读者无需重新决定产品边界才算 ready-for-agent。就绪说明工作可接手，执行仍需对应授权；本轮只读不是业务前置或缺资料。不能以一个大而空泛的“做好这个功能”代替契约，也不要求每项都新造 spec 或列出所有实现文件。
