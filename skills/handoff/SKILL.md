# Handoff: 会话交接

首行内联带上 🥷，不要单独起段。

交出当前任务的可恢复状态，或接入先前工作并核对现场。交接保留上下文，后续行动仍按本任务有效授权推进。

## 调用边界

首次进入本技能时，须由用户显式输入 `/handoff`、`$handoff`、`调用 fskill 的 handoff`、`用 fskill handoff skill`、`invoke fskill handoff`、`use fskill handoff skill`，或 Desktop 根分发器已从 `/fskill handoff` 选中本技能，或当前会话里用户已进入 `/f-mode` 且 f-mode 点名了本技能。同一任务中的回答、补充、纠正和继续请求沿用已显式调用的技能，无需每轮重复命令；f-mode 关闭时，新任务或切换技能仍需显式调用；f-mode 开启时可由 f-mode 按当前目标重新选择。若宿主仅因语义相似自动加载本技能，不应用下文流程，按普通 Agent 请求继续处理。

## 交付约定

- 目标: agent 得到范围清楚、能与现场核对的工作上下文，交出或恢复任务时不重做已有结果。
- 完成条件: 当前状态、关键决策、已完成/待完成、相关文件和授权边界齐全；接入恢复时，会漂移的关键状态已核对或明确标为未验证。
- 依据: 当前会话、已有交接与产物、范围内相关历史，以及当前代码、验证和外部状态。
- 交付形式: 交出时提供 Markdown 交接文档；接入时提供简短恢复摘要，要求保存时才写文件。

## 长期上下文预检

恢复时先读取用户提供的状态摘要或项目既有恢复入口。历史材料与可选记忆只作定位背景；当前 Git、文件、验证与相关外部状态优先于旧记忆和历史总结。详细范围与取证方式见 [接入先前工作](references/resume-context.md)。

## 模式选择

| 用户目标 | 处理 |
|---|---|
| 交出当前会话供后续接手 | 按交接流程保留当前状态与指针 |
| 接续先前会话，或回忆某主题的近期工作 | 按 [接入先前工作](references/resume-context.md) 恢复并核对状态，不重建已有充分上下文 |

## 交接流程

用户需要选择继续、压缩、旁路委派或跨会话移动时，读取 `references/context-transition.md`；明确的交接请求直接按本流程交付，不先增加一次选择。未来自动运行的交接也按该参考写清触发、状态和完成条件。

1. 盘点对话：在整段会话里找出已完成和未完成的事项、做出的决策、产出的文件。
2. 写状态：一句话说清现在在做什么、卡在哪里。
3. 写决策：每条一行，写做了什么决定、为什么。
4. 列出实际的已完成和待完成，保持简洁；保留接手所需的范围、授权和阻塞，不凑条数。
5. 列出相关文件：引用路径或 URL，不复制内容。
6. 掩盖密钥、密码、token 和 PII。
7. 末尾写建议技能：一行一个技能名。
8. 按保存规则交付文档，并说明保存路径或仅预览状态。
9. 如果用户给了参数，把它当作下一个会话的重点方向，只保留相关内容。

## 硬性规则

- 交出文档时，用户指定路径或文件名就遵循该要求；否则默认保存到工作区根目录 `HANDOFF.md`。已有文件默认追加带分隔线的新交接，只有明确要求替换时才覆盖。明确只要预览或不写文件时直接回复；接入恢复默认只交摘要，要求保存时才写入指定位置。
- 引用已有产物，不复制正文。
- 掩盖密钥、密码、token 和 PII。
- 交接文档是给 agent 读的，不做去 AI 味处理。清晰、结构化优先于自然。
- 不念空泛开场和总结腔。首行内联 `🥷` 和当前状态，后续列出决策与工作清单。
- 不用表格，不做加粗和格式装饰。

## 常见误区

| 行为 | 规则 |
|------|------|
| 没有指定交付位置 | 按保存规则选择默认路径或只读预览，保存后告知路径 |
| 在文档里复述已有文件的内容 | 只引用路径或 URL |
| 漏掉了密钥或 token | 写入前检查整份文档中的敏感信息 |
| 加了“本次会话完成了以下工作：”等开场 | 首行内联 `🥷` 和当前状态 |
| 篇幅过长 | 压缩重复内容，不为一屏限制丢失接手所需的边界和未完成事项 |

## 输出

接入恢复时按参考交付当前状态、相关工作线、未解问题和下一步；交出文档时使用以下格式。

```text
🥷 <一句话当前状态>

关键决策
- <决定>：<原因>

已完成
- <条目>

待完成
- <条目>

相关文件
- `path/to/file` 或 URL

建议技能
- skill-name
```
