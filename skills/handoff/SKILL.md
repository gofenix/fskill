# Handoff: 会话交接

首行内联带上 🥷，不要单独起段。

## 交付约定

- 目标: 让下一位 Agent 拿着精准指针、授权边界与阻塞项直接继续，不漏关键决定也不重干已完成的活。
- 完成条件: 交接时写明状态、决策、已完/待完、阻塞、授权边界和脱敏文件路径；恢复时现场核对过 Git、文件与验证状态。
- 依据: 当前会话真实进度、Git 状态、产出的文件路径与外部检查状态。
- 交付形式: 交出时写入 `HANDOFF.md`（或用户指定路径，预览则只回复）；恢复时给简短现状摘要。

## 调用边界

仅在显式调用 `/handoff`、`$handoff`、fskill 限定入口或已开启的 `/f-mode` 选中时执行；同一任务追问沿用。不用于常规文案编辑或默认实施历史未授权计划。

## 交出与恢复

- **交出当前会话**：提取整段会话中的真实进度，**只引路径和 URL、不抄正文**，写前脱敏任何密钥、密码、token 与 PII。默认写入工作区根目录 `HANDOFF.md`（已有内容时分隔追加，用户明确要求才覆盖；仅要预览则不写文件）。给 Agent 读的交接不做去 AI 味处理，保持简洁平铺模板（首行 `🥷 <一句话状态>`，不用表格和加粗装饰）：关键决策 / 已完成 / 待完成 / 当前阻塞 / 授权边界 / 相关文件 / 建议下一步。
- **恢复先前工作**：先读目标交接文档或最近摘要，再立刻核对当前分支、`HEAD`、`git status`、相关文件与检查状态。**现场状态永远优先于旧交接总结**；把变化和未核实项说清后按本任务有效授权继续。
