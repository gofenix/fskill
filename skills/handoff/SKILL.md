# Handoff: 会话交接

首行内联带上 🥷，不要单独起段。

交出当前任务的可恢复状态，或接入先前工作并核对现场。交接保留上下文，后续行动仍按本任务有效授权推进。

## 交付约定

- 目标: 让下一位 Agent 拿到边界清楚、能核对现场的上下文，交接或恢复时不重复干已经做完的活。
- 完成条件: 当前进度、关键决定、已做和待做、相关文件、当前阻塞和授权边界齐全；恢复任务时，容易变化的状态已经现场核对或标明未核实。
- 依据: 当前会话、已有交接文档和产物、相关历史，以及当前代码、测试和外部状态。
- 交付形式: 交出时写 Markdown 交接文档；恢复时给简短的现状摘要，用户要求保存再落盘。

## 长期上下文预检

恢复时先读取用户提供的状态摘要或项目既有恢复入口。历史材料与可选记忆只作定位背景；当前 Git、文件、验证与相关外部状态优先于旧记忆和历史总结。详细范围与取证方式见 [接入先前工作](references/resume-context.md)。

## 调用边界

仅在用户显式调用 `/handoff`、`$handoff`、fskill 限定入口，或已开启的 `/f-mode` 选中时执行；同一任务里的追问和纠正继续沿用，不用每轮重复命令。f-mode 关闭时，新任务或切技能需重新点名；宿主仅因语义相似自动加载，或文中只是提到命令名时，按普通请求处理。不用于常规写作、编辑、去 AI 味或自动实施历史计划。

## 模式选择

| 用户目标 | 处理 |
|---|---|
| 交出当前会话供后续接手 | 按交接流程保留当前状态与指针 |
| 接续先前会话，或回忆某主题的近期工作 | 按 [接入先前工作](references/resume-context.md) 恢复并核对状态，不重建已有充分上下文 |

## 交接流程

用户需要选择继续、压缩、旁路委派或跨会话移动时，读取 [选择交接与上下文边界](references/context-transition.md)；明确的交接请求直接按本流程交付，不先增加一次选择。未来自动运行的交接也按该参考写清触发、状态和完成条件。

实际委派旁路任务前读取 [委派预算](references/delegation-budget.md)；记录交接建议不等于获得派工授权。

1. 盘点对话：在整段会话里找出已完成和未完成的事项、做出的决策、当前阻塞、授权边界和产出的文件。
2. 写状态与决策：一句话说清现在在做什么、卡在哪里；每条决策写做了什么决定和原因。
3. 列出实际的已完成和待完成，引用相关文件路径或 URL（不复制内容），并掩盖密钥、密码、token 和 PII。
4. 末尾写建议技能：一行一个技能名。
5. 如果用户给了参数，把它当作下一个会话的重点方向，只保留相关内容。
6. 按保存规则交付文档，并说明保存路径或仅预览状态。

## 硬性规则

- 交出文档时，用户指定路径或文件名就遵循该要求；否则默认保存到工作区根目录 `HANDOFF.md`。已有文件默认追加带分隔线的新交接，只有明确要求替换时才覆盖。明确只要预览或不写文件时直接回复；接入恢复默认只交摘要，要求保存时才写入指定位置。
- 引用已有产物，不复制正文；写入前检查并掩盖密钥、密码、token 和 PII。
- 交接文档是给 agent 读的，不做去 AI 味处理；清晰、结构化优先，不念空泛开场和总结腔。
- 首行内联 `🥷` 和当前状态；不用表格，不做加粗和格式装饰；压缩重复内容，但不丢失接手所需的授权边界、阻塞和未完成事项。

## 输出

接入恢复时按参考交付当前状态、相关工作线、未解问题和下一步；交出文档时使用以下格式。

```text
🥷 <一句话当前状态>

关键决策
- <决定>：<原因>

已完成
- <条目>

待完成
- <条目>

当前阻塞
- <阻塞项，或无>

授权边界
- <当前有效授权与不得自动执行的动作>

相关文件
- `path/to/file` 或 URL

建议技能
- skill-name
```
